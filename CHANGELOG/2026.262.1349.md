# 2026.262.1349 — feat(scripts): pr_state_watch.sh — stop on a terminal PR state

## Summary of changes

Adds `scripts/pr_state_watch.sh` — a PR poll that **stops the instant a terminal state is reached**, so "keep polling" can never be the wrong answer.

It distinguishes two states that look identical to `gh pr checks`:

- **MERGED** (exit 0) — landed.
- **BLOCKED** (exit 2) — a real verdict BLOCK, **or** the **POISON** state: a green same-head re-dispatch stuck behind an older same-name FAILURE in GitHub's collapsed rollup. GitHub collapses same-name check-runs to the WORST conclusion, so a newer SUCCESS does not clear an older FAILURE. Measured on `opencharly/plugin-vm#39`: the PR read `mergeStateStatus=BLOCKED` while its validator verdict was PASS. The remedies differ (a real BLOCK → fix the finding; POISON → push a NEW commit or add the per-repo concurrency dedupe).
- **CLOSED** (exit 3) — abandoned.

`gh pr checks --watch` reads the collapsed rollup and **cannot see POISON**; a hand-rolled `while`/`sleep` loop is the R4 band-aid. This replaces both. Exit codes: `0` MERGED · `2` BLOCKED · `3` CLOSED · `4` TIMEOUT · `5` ERROR.

**Files:** `scripts/pr_state_watch.sh` (new, executable). This `scripts/` dir is hand-authored and preserved by generation (marketplace CLAUDE.md lists it among the non-generated paths), alongside `refresh-refs.sh` and `squash_body.py`.
