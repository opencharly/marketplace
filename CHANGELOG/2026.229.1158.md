## 1. The emitted build step no longer names bash

The Containerfile emitter stopped hardcoding `bash` (see the sdk's entry for this CalVer), so the
per-verb emission table in `/charly-build:generate` described an interpreter the emitter no longer
names. Corrected at the source, along with two trailing explanations that had gone stale with it:

- the `download` row's `bash -c '…'` → `<shell-probe> '…'`, and "so bash expands
  `${BUILD_ARCH}`" → "so the shell expands";
- the `cmd` row's `bash -c $'…'` → `<shell-probe> <<'OVCMD'`. **This row was stale in a second,
  independent way**: the `cmd` emitter uses a heredoc, not ANSI-C `$'...'` quoting, and had done
  for some time. The trailing sentence explaining the ANSI-C quoting went with it. Both forms were
  read off a freshly emitted Containerfile rather than inferred.
- a new paragraph defines `<shell-probe>` so the table stays readable on its own.

`apk` became a valid package format (see the spec entry), so the enumerations that list the formats
gained it: the per-layer emission order in `/charly-build:generate`, the same list in
`/charly-internals:generate-source`, and `Valid: rpm, deb, pac, aur` in `/charly-image:image`.

The `charly candy add-rpm` / `add-deb` / `add-pac` / `add-aur` rows in `/charly-image:image`,
`/charly-image:layer` and `/charly-build:charly-mcp-cmd` gained `add-apk`. Those rows enumerate

## 3. The Debian-family `distro:` trap

`/charly-internals:vm-spec` gained the omission trap: on a Debian-family cloud image, leaving
`source.distro` unset rendered `openssh` plus `systemctl enable --now sshd` — a unit Debian and
Ubuntu do not have — and with cloud-init's deliberate `mask ssh.socket` that left a
socket-activated sshd masked and never started. The guest booted fully and served nothing.

## Why this is a narrow file set, not a wholesale regeneration

Worth recording, because the first attempt was wrong in a way that looked right. Running
`charly marketplace generate` wholesale produced **21** modified files, and the extra 16 were not
drift to tidy up — they were **reverts**. Regeneration wanted to delete ~500 lines of prose that
had legitimately landed here, including 317 lines from
`git-workflow/references/evidence-and-freshness.md` and 107 from `agents/pr-validator.md`.

The cause is the projection ordering this repo works under: **a projection merges before the
superproject source that pins it.** So prose can be correct and landed *here* while its candy
source is still in flight on a superproject branch. Regenerating from a superproject tree that
lacks that pending source does not "bring the projection up to date" — it drags it backwards, and
the diff gives no hint, because a reverted projection looks exactly like a projection that was
never stale.

The fix is scope, not tooling: this change keeps only the projections of the candy files it
actually edited, and every deleted line across those files is one it deliberately replaced.
