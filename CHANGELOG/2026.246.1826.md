# 2026.246.1826 — docs(agents): add subagent model resolution rules

## Summary

Add a "Subagent model resolution (pi harness)" section to the agents skill: two operational rules verified 2026-09-03 —

1. **Explicit `extensions:` in an agent config disables ambient extensions in the child** — pi-subagents launches the child with `--no-extensions` when the agent config carries an explicit `extensions:` list, which unloads model-provider extensions (e.g. pi-ollama-cloud) so a provider-qualified model becomes unresolvable ("Model not found") and the child falls back to a wrong provider. Fix: agent configs should NOT carry explicit `extensions:`, or must include the provider extension.
2. **Provider-qualified ids pass through a stale registry snapshot** — pi-subagents (opencharly fork, PR #1 / 4abd9597) passes an explicit provider-qualified model id through raw when the session-start snapshot misses it.

## How tested

- Both rules verified live (2026-09-03): `--no-extensions --list-models` shows 0 ollama-cloud models vs 20 without; adding the pi-ollama-cloud extension to the child launch resolves `ollama-cloud/deepseek-v4-flash:0731`; subagent dispatch runs on the correct model with `error: null`.
