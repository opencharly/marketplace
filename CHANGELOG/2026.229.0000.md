# 2026.229.0000 — the Containerfile `cmd:` emitter is a heredoc, not ANSI-C quoting

**This is a REGENERATION, not an authored edit.** All five files carry
`GENERATED by `charly marketplace generate` — DO NOT EDIT`; their source is the `skill:` entities in
`candy/charly-build/charly.yml` and `candy/charly-internals/charly.yml`, landing as
`opencharly/charly#<TBD>`.

## What arrives

The emitter documentation described a mechanism the code no longer uses, and named three symbols —
two of which do not exist anywhere in the tree.

| Claim | Reality |
|---|---|
| `emitCmd` emits `bash -c $'…\n…'` (ANSI-C quoting) | `EmitCmd` emits a single-quoted heredoc `<<'OVCMD'`, behind a bash-preferred/POSIX-fallback shell prefix |
| `shellAnsiQuote(s)` is the helper that does it | **No such symbol exists** — in the superproject or the sdk |
| `shellSingleQuote(s)` quotes LABEL and env values | The helper is `spec.ShellQuote` |
| `stageInlineContent(...)` stages `write:` content | Exported and relocated: `StageInlineContent` in `sdk/deploykit/tasks_stage.go` |
| `tasks.go` holds "all task emission logic" | It is **64 lines with ONE function**, `invokeOpEmitFragmentOpt`; all emission lives in `sdk/deploykit`. It holds no shim and cannot (P16 import purity forbids `charly/` importing the sdk) |

The ANSI-C form was not merely renamed — it was **abandoned**, because it requires bash and a
busybox base has none. That is the same defect the `sdk` leg fixed by routing both emit sites through
`BuildStepShellDashC()` / `BuildStepShellHeredoc()`; this documentation simply never caught up.

## Why it was worth fixing rather than filing

A reader following the old text would look for `shellAnsiQuote` to understand quoting, find nothing,
and have no way to tell whether the symbol was renamed, relocated, or removed. Two of the three names
had no referent at all, so the prose could not be repaired by inspection — only by reading the
emitter. The corrected text names the mechanism (`<<'OVCMD'`) rather than a helper, so it stays true
across future renames, and states why the ANSI-C form is gone rather than silently dropping it.

## Provenance

Ground truth was read out of `sdk/deploykit/tasks_emit.go` at the pinned sdk commit and confirmed by
a live podman build of the emitted directive — the heredoc form on a busybox base preserves single
quotes, double quotes, `$HOME`, backticks and embedded newlines; the pre-fix `bash -c` form on the
same base fails `exit 127`.

Regenerated on `origin/main`, then filtered to the five files whose diffs are attributable to these
symbols. A wholesale regeneration from this tree also rewrites `pr-validator.md`, the git-workflow
references, `core/skills/clean`, and the ollama skills, and **deletes**
`ollama/skills/ollama-cli/SKILL.md` — none of which belong to this change. Those are drift from candy
sources not yet on superproject `main`, and reverting them is deliberate, not an oversight.

## Round 2 — the first fix named non-existent symbols too

A validator failed round 1 with the observation that lands hardest: **this change's own thesis is
that documentation naming non-existent symbols is a defect, and its replacement prose named
non-existent symbols.** Four blocking findings, all confirmed against the code:

| Round-1 text | Reality |
|---|---|
| ``tasks.go`` is "a thin shim to `deploykit.Generator.EmitTasks`" | `charly/tasks.go` is **64 lines with ONE function**, `invokeOpEmitFragmentOpt`. It cannot shim a `deploykit` method — the P16 import-purity gate forbids `charly/` importing the sdk at all |
| `emitPluginFragment` → `Invoke(OpEmit)` | **Zero declarations** in either module. The real function is `invokeOpEmitFragmentOpt` |
| `case "command": emitCmd (RUN bash -c …)` | The exact `bash -c` form this entry retracts, surviving in the same file 45 lines above its own retraction |
| `emitDownload` row: `bash -c`, and `curl … \| <extractor>` | `EmitDownload` emits the shell probe, and fetches to a **content-addressed cache file** — there is no pipe |

Two more came from a cold-reader pass on the rendered pages: `generate.md`'s `write:` row emitted a
`--from=<layer-stage>` that `EmitWrite` never writes (the source is a build-context path), and the
same page's `download:` row claimed the pipe.

**The root cause is one sentence:** the greps were pointed at the claims being RETRACTED and never at
the claims being ASSERTED. A correction is a new claim and earns no exemption from the test that
caught the old one. Every Go symbol the corrected prose now names was checked to exist before this
round was pushed — including method receivers, which a bare `func <name>` grep misses.

**Scope grew accordingly.** 52 lowercase emitter names (`emitTasks`, `emitCmd`, `emitDownload`,
`emitWrite`, `emitCopy`, `emitMkdirBatch`, `emitLinkBatch`, `emitSetcapBatch`, `emitBuild`) were
renamed to the exported forms that actually exist in `sdk/deploykit`; the lowercase spellings exist
nowhere. One stale test reference (`TestEmitPluginFragment_BuildTimeOpEmit`, absent) now names the
real gate, `TestOpActsInBuildDeploy_PlacementAgnosticBuildEmit`.

**Two stale test-name references are deliberately NOT fixed here** — `TestNsRepoIdentity` and
`TestImportNamespace_DivergentVersionMutualCycle`, both absent from every `*_test.go`, both
pre-existing, and both a different claim family from the emitter symbols. Guessing replacements is
precisely what failed round 1, so they are routed rather than invented.
