# 2026.242.2229 — feat: project the wl skills from their new home, and the omarchy skills

## Summary

Four skill-repo changes merged today and none of them had reached the corpus, because the
corpus is generated from this repo's authored refs list and those pins had not moved.

## The wl skills changed OWNER, which is why this PR is load-bearing

`wl-skill` and `wl-overlay-skill` moved from `layer-charly-check` (a repo that ships none of
the `wl:` verb's code) into `opencharly/plugin-wl` (which ships all of it). That move is
three PRs, and this is the third:

1. `opencharly/plugin-wl#7` — added them there, tagged `v2026.242.2204`.
2. `opencharly/layer-charly-check#4` — removed them from there, tagged `v2026.242.2213`.
3. **this PR** — bumps the `layer-charly-check` pin AND adds
   `@github.com/opencharly/plugin-wl/candy/plugin-wl:v2026.242.2204`, in ONE change.

Both halves must land together. A skill `name:` is marketplace-globally-unique, so adding
plugin-wl's ref while layer-charly-check still carried the skills would put two `wl` skills
in one generation; bumping layer-charly-check alone would delete them from the corpus.
`plugin-wl` was not previously a ref at all — that is the reason step 3 exists rather than
the move being self-executing.

`family: check` is unchanged on both skills, so they regenerate to the same published paths
(`check/skills/wl/`, `check/skills/wl-overlay/`) and every `/charly-check:wl` cross-reference
in the other skills stays valid.

## What else this projects

- **`check/skills/wl/SKILL.md`** — now also documents the `hypr-*` family, which the skill
  had never mentioned despite plugin-wl serving it, including the new `hypr-layers` method.
- **`check/skills/check/references/verb-catalog.md`** — the shared-modifiers table gains
  `eventually:` and `retry_interval:`, which were absent even though the same skill used
  them in worked examples. A reader consulting that table concluded charly cannot poll.
- **`distros/skills/omarchy/`** and **`vm/skills/omarchy-vm/`** — new. The Omarchy base image
  and its three VM entities have shipped and are gated by five disposable beds; no skill
  mentioned any of them.
- **`vm/skills/vms-catalog/`** — `kind: vm` is documented as sourced four ways
  (`cloud_image`, `bootc`, `bootstrap`, `iso`) instead of two, and `#DistroID` as 14 ids
  instead of 13.
- **`vm/skills/{arch-cloud-vm,vm}/`** — catching up with `vm-charly-vm#2`, already merged
  there but never projected.
