## The defect

The page shipped a probe recipe that fed `git merge-tree --write-tree` into a bare command substitution. `merge-tree` exits 1 on conflict and prints the tree oid followed by the conflict stages, so `git commit-tree` rejects the multi-line capture — and the obvious repair is worse than the bug. `head -1` yields a real, checkoutable tree whose files contain `<<<<<<<` markers, and the recipe's whole purpose is to run a gate inside that tree. A gate that passes there has certified conflict markers.

Both `merge-tree` call sites now guard on the **exit status** rather than the output shape.

## The root cause was the frame, and the frame's fix was incomplete

The page divided its content into epistemic and mechanism sections and promised execution only for the mechanism half. The one broken shell recipe sat in an *epistemic* section, exempted by that wording, so patching the recipe alone would have left the next one exposed. The rule is rescoped to **content**: every runnable command and every mechanism claim is executed before publication, wherever it sits.

That rescope was itself incomplete, and the gap produced the very next error on this cutover. It fixed *what* gets executed and never *where*: a drift figure was executed, correct, and false, because it was taken with the submodules at their repo tips and reported as a fact about `main`. The rule now carries a **provenance clause** — a measurement is publishable only with its tree identified: which commit, which submodule shas, which working-tree state. "On main" is a claim about pinned gitlinks.

## R6 tree-safety, in the recipe rather than in the reader

The probe used a fixed `/tmp/gate-probe` and a `git worktree remove --force` that never checks whose worktree it is removing. A second probe's `add` correctly refuses with exit 128 — and then, in a script without `set -e`, its cleanup returns 0 and **destroys the first probe's worktree**, uncommitted contents included. Reproduced before fixing. The recipe now takes a per-run `mktemp -d` (`worktree add` accepts an existing empty directory, so this is race-free) and nests the cleanup inside the add's success branch.

## Recipe corrections from review

- **Paste-safety.** Neither recipe contains `exit` any more. Both are meant to be pasted into an interactive shell, where an `exit` on the failure path closes the terminal; nesting achieves the same guarantee. The paragraph explaining that fix was itself left crediting the `|| exit 1` it replaced, and is corrected with it — the third time in three review rounds that a correct fix here orphaned the prose describing it. That pattern is now written into "Sweep for what the fix invalidated" as an operational rule: grep for what DESCRIBES the construct you changed, not for the construct, because searching for the thing you edited only finds the place you already fixed.
- **The identity test no longer runs the wrong probe.** Previously the `else` branch advised "use the numstat form below" while `git diff --numstat` sat unconditional below it and had already run — on the clean path too, silently, with a second wasted `merge-tree`. The numstat is now inside the conflict branch, and it reuses `$RESOLVED` (which is assigned even when the substitution fails, holding the tree oid plus the conflict stages) instead of invoking `merge-tree` again.
- **`head -1` is scoped by intent, not by location.** The old note claimed it was "correct here and nowhere else on this page" — false, and falsified by the same diff, since the evidence block uses it too. It is right when you want the conflicted tree as DATA to diff or inspect, and wrong the moment you will RUN anything inside the resulting tree.
- **The evidence block carries its fixture** — `git init`, the two branches, the conflicting file — so a reader can reproduce it, on the page whose new rule is that everything runnable is executed before publication.
- **"The third line"** now reads "the third COMMAND", which is what it meant in a multi-line fence.
- **A contradiction predating this cutover is fixed rather than left.** The cross-repo section said the two drift directions "fail the same way", two paragraphs above a table and a sentence establishing that one carries an extra `(stale)` marker and is "the more legible of the two". It now says both fail *loudly* and are not equally legible.
