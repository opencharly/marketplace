## The false mechanism claim

The page said the orphan scan **"keys on the GENERATED HEADER, not on the path"**, and that a
header-less file **"is invisible to drift wherever it sits"**. Read against `scanGenerated`, both
directions are wrong. It has three arms and only the first reads any file's bytes:

1. it walks `plugins/<family>/skills` and `.../agents`, collecting whatever carries the header;
2. it adds a fixed list of known paths — each family's `plugin.json`, `.codex-plugin/plugin.json`
   and `.mcp.json`, plus `marketplace.json`, `profiles.json`, `setup` — if they exist, header or
   not;
3. it takes every file under `.claude/hooks/` outright.

So the header decides only inside the walked trees, and a header-less file is invisible only when it
**also** sits outside the known paths and the hooks directory — which is exactly the condition under
which `plugins/README.md`, `CHANGELOG/`, `LICENSE` and the scripts survive regeneration, and exactly
what `prune.go`'s own comment states 25 lines above the function.

The sentence predates this cutover; the previous round made it worse by adding *"one banner line is
the whole detection surface"*, which is true only where the canary sits. It survived because it was
the **unchanged** part of a diff an author and two validators were reading for what changed — the
condition under which a false mechanism claim is hardest to see.
