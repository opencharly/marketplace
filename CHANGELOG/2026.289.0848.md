# 2026.289.0848 — fix(lint): class-6 arm's sweep claims must be backed in their own bullet

## Summary

`scripts/pr_body_lint.py`'s class-6 arm accepted **any** later `$ ` fence in the same section as proof for a claim, without looking at the claim at all:

```python
backed_later = any(
    kk == "fence" and any(t.lstrip().startswith("$ ") for t in tt)
    for kk, _, tt in bl[k + 1 :]
)
```

So the identical claim fired in `## Summary` and passed one section later — and `## Rulebook compliance` is where a sweep claim naturally belongs, because that section routinely **ends** with a fenced command (an R5 grep, an R7 test run, an R9 version check), which then backed every claim above it.

This scopes the requirement to the claims that actually need a command, and nothing else:

```python
SWEEP_CLAIM = re.compile(r"\bonly occurrence\b|\b(?:was|were|been) swept\b", re.IGNORECASE)
```

A **sweep** claim asserts that a search was exhaustive — the two patterns are named in the `SWEEP_CLAIM` fence above — so only a pasted command can support it, and that command belongs to the bullet asserting it. An ordinary rule assertion — "`git status` was checked", "the artifact was verified after the build" — asserts that a **step was done**, and `## Rulebook compliance` is *designed* to be backed by the section's evidence.

**That scoping is measured, not asserted.** Requiring bullet-local backing for *every* `CLAIM` match — the obvious fix, and my first implementation — fires on **7 of 36 real merged bodies**, and every one is an ordinary rule bullet: `sdk#422`'s R6, `marketplace#489`'s R7, `plugin-check#109`'s R9, `plugin-check#120`'s R6.

Two implementation details, both from defects found in my own first attempt:

- the bullet-local check **replaces** `backed_later` for the sweep subset rather than `and`-ing with it — `CLAIM and not POINTER and not backed_later and not own_bullet` is a **boolean no-op**, because whenever `backed_later` is True the condition is already False;
- block offsets are computed exactly, not via `body_lines.index(ln)`, whose first-occurrence semantics mislocate a repeated line.
