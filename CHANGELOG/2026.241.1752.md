# 2026.241.1752 — fix: remove the unwired hook scripts from this repo

## Summary of changes

Phase E.3 of the candy de-submodule cutover. `.claude/hooks/` here holds four scripts —
`pre-commit-gate.sh`, `pre-push-gate.sh`, `gitcmd.py`, `gate_test.py` — that **enforce nothing in
this repo**.

Three independent checks, all run *before* deleting:

| # | Check | Result |
|---|---|---|
| 1 | **Are they wired?** Claude Code runs a hook only when `settings.json` declares it under a `PreToolUse` event. | **No.** This repo's `.claude/settings.json` has no `hooks` key at all — only `enabledPlugins` and `extraKnownMarketplaces`. |
| 2 | **Does anything reference them?** | **No.** The only matches for their names anywhere in the repo are the scripts referring to each other. |
| 3 | **Are they still generated?** They were output of the generator's `emit_hooks` job. | **No.** Phase B deleted that job — `emit_hooks.go` no longer exists in `plugin-marketplace`. |

Unwired, unreferenced, unmaintained. An inert file that **looks** like a gate is worse than no file:
it invites the belief that this repo has a commit/push gate when it has none.

## What I did NOT delete, and why

The plan bundles `.claude/settings.json` with them. **It is not dead**: its `enabledPlugins` (26) and
`extraKnownMarketplaces` are what make a Claude Code session opened in this repo load the
marketplace's own plugins. It was generated once too, but unlike the hooks it still does something,
so it stays and is now hand-maintained.

## One thing worth stating, because it made me hesitate once already

charly carries the **same four scripts, also unwired**. That is a question about charly, not about
whether *these* copies do anything here — they do not. The gates that actually run in this org are
wired by the **umbrella's** `.claude/settings.json`, which declares `PreToolUse` hooks and is
untouched by this PR. (Those are the gates that have been blocking my own malformed `git commit`
invocations throughout this cutover, so they are demonstrably live — and demonstrably not these
files.)
