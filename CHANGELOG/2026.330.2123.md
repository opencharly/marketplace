cannot be published fails it. The retirement contradiction it raised first is the reason the list
edit is in this PR:

### Spike

The two shapes for "publish a restored repo's skills", both exercised on the real generator:

```

charly marketplace: the refs list pins retired repo(s): @github.com/opencharly/pod-kde-vnc:v2026.330.1628
  — remove the pin, or drop the retirement from retired.cue          (exit 1)

# (b) add the pin AND drop the repo from retired.cue (CHOSEN) — generation succeeds and emits the
#     projections:
rc=0, five new skill dirs, +30 index rows, +2 DISPATCHER rows
```

Winner: (b). The retirement list is a corpus-level denial that outranks a stale pin by design
(opencharly/plugin-marketplace#63), so a restored repo must leave it in the same change.
