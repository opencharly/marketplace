# 2026.241.1743 — feat: resolve the marketplace verb from this repo, not a borrowed charly checkout

## Summary of changes

Phase C.2 of the candy de-submodule cutover. `charly marketplace` is an **out-of-tree command
plugin**, and the word only enters the CLI grammar when charly runs inside a project whose prescan
declares it. This repo declared nothing, so:

```
$ charly marketplace generate --root . --out .
Usage: charly <command> [flags]        # the GENERIC usage
exit 80
```

…and `deploy.yml` / `refresh.yml` had to `cd` into a charly checkout purely to **borrow the
grammar**.

| Added | |
|---|---|
| `charly.yml` (root) | a `discover:` and nothing else. Not a box/deploy project — the corpus at the root is generated output, and `candy/charly-marketplace` is the refs list it comes from. |
| `tools/marketplace-cli/` | a thin **re-export shim** — the same shape charly uses for `generate-packages`: a candy declaring `plugin.providers: [command:marketplace]`, plus a `cmd/serve` main handing the external module's provider to `sdk.Main`. Nothing is reimplemented. |

## A remote ref could not do this

A project pinning only `@github.com/opencharly/plugin-marketplace/…` **still exits 80** — measured on
the `generate-packages` probe — because a remote candy ref does **not** register a command word. The
declaration has to be local, and the host builds this directory resolved through its own `go.mod`
require (`source:` is identity metadata, never a fetch).

## It also closes a pin hole

Resolving the word from a charly checkout fetched:

```
Downloading github.com/opencharly/plugin-marketplace:main...
```

A **mutable** ref — the generator could change under CI without any pin moving. The shim pins it by
`go.mod` require at `v0.2026241.1531` instead, and that line is gone from the output.

Both workflows drop the `cd /tmp/charly`. The charly clone stays, now purely to **build the
binary** — the two `cd /tmp/charly/charly && go build` steps are unchanged.

### A mistake worth recording

`git add -A` swept in `tools/marketplace-cli/serve` — a **31 MB binary** left by my own
`go build ./...` while testing the shim. `git show --stat` after the commit caught it, which is
exactly what that check is for. The branch was already pushed, so it is removed by an **added
commit** (`a9eb602`) rather than an amend — no force-push.

This is the **second** time this exact artifact has slipped in; `opencharly/charly#455` was the
first, caught before its push. The `.gitignore` added here is what makes a third impossible rather
than relying on noticing again.
