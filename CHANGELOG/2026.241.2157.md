# 2026.241.2157 — feat: project the two punktfunk skills into the corpus

## Summary

Projects the two punktfunk skills into the corpus. punktfunk shipped as a full image
family — the candy (`opencharly/layer-punktfunk`), the `punktfunk:` check verb
(`opencharly/plugin-punktfunk`), a box and two disposable beds
(`opencharly/distro-cachyos`) — but **nothing in the corpus documented any of it**, so no
harness loaded a skill for it.

```
punktfunk/skills/punktfunk-host/SKILL.md   the host candy
check/skills/punktfunk/SKILL.md            the punktfunk: check verb
```

The change is three things that must land together, because the drift gate requires the
committed corpus to be a no-op regeneration of the refs list:

1. **Refs** — advance `pod-charly-hooks` to `v2026.241.2134` (the tag carrying the new
   `punktfunk` family) and add the two skill-bearing repos at
   `layer-punktfunk:v2026.241.2145` and
   `plugin-punktfunk/candy/plugin-punktfunk:v2026.241.2146`.
2. **Regenerated corpus**, committed in the same PR.
3. **README** — its bucket tables are hand-authored, so the images bucket, the images table
   and the `charly-check` probe list are updated by hand.

Closes opencharly/marketplace#252.

**Family placement:** `punktfunk-host` goes in the new `punktfunk` family, following the
one-family-per-image-family pattern. It is deliberately *not* filed under `selkies`, which
is "the selkies-desktop family (Wayland desktop in a container with VNC + Chrome)" —
punktfunk is a host daemon with its own protocol and a management plane, not a
containerised desktop stream. The verb skill goes in the existing `check` family with the
other probe verbs.
