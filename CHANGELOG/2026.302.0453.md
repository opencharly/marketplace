## Summary

Head `f4ebcd2d2c91cde22fdd7f01ab7263645828e7fb` — 6 files changed, 618 insertions(+), 53 deletions(-).

The daily refresh assembled a PR body that claimed the tier `fully tested and validated` and promised "exact gate, commands, and pasted output", while carrying only the gate STEP's SOURCE, pasted out of `deploy.yml`. The gate itself runs on the PR, and the PR is created after the body is written — so the body claimed a tier it could not back at the moment it claimed it. The validator BLOCKed that body for exactly that, and it would block every later refresh the same way.

So the gate is now RUN in the PR step, on the tree the PR commits, and the gate's own output is pasted into the body as item 4.

The check is now `scripts/drift-gate.sh` — ONE implementation, run by the `marketplace` workflow (`deploy.yml`) on every PR and by the refresh job on the tree it commits. Before this change the check lived in both workflows: two implementations of one gate drift apart silently, and the copy nobody runs is the one that goes stale (R2).

**And the instrument was wrong.** `git status --porcelain` reports the INDEX column as well as the worktree column, and the refresh job stages the regenerated corpus on purpose — so the index differs from HEAD by design and the old condition was true BY CONSTRUCTION. Measured 2026-10-29 on the refresh's own tree with the pinned generator (charly `2026.296.2116`): the check aborted with DRIFT on a tree that had not moved at all, listing the whole staged corpus. Every refresh run would have aborted before the body was assembled and no PR would ever have been opened — the corpus would freeze, the exact failure the workflow exists to prevent (#413, #451).

The gate now asks the question it means to ask: "did the tree move since the index was set" — the working tree against the index (`git diff --quiet`) and the files that are in no index at all (`git ls-files --others --exclude-standard`), the half `git diff` alone misses, because a generator that emits NEW artifacts creates them as untracked files.

`scripts/drift_gate_test.sh` is the gate's control, and it holds the arm that catches the defect above: a STAGED corpus with an unmoved tree — the refresh job's own shape — must PASS the gate. Two mutations (the wrong instrument, and the untracked half dropped) must each turn the suite red, or the process exits non-zero.

The elision notice's class-1 claim is corrected as well: the progress lines name EVERY ref the generator resolved, so the pins this refresh advanced are a SUBSET of the refs those lines name, and the changed-file list names PATHS, not refs. The earlier wording — that every ref the progress lines name "is already listed above" — was false, and the validator BLOCKed the body over it.

**One finding crosses a repo boundary.** The published `marketplace` skill names the gate's old instrument, so this change makes that one parenthetical stale. The skill is authored in opencharly/plugin-marketplace — the source the refs list pins DIRECTLY — so the correction is a producer PR there, and opencharly/plugin-marketplace#56 carries the RCA. The corpus projection, the docs mirror and the docs recipe page are all projections of that one file, so the correction reaches all three at the next corpus regeneration.

Closes #593
