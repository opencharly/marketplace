# 2026.230.2101 — the ollama page stops hardcoding a container port as a host port

Re-projected from `candy/ollama/charly.yml` after two cold-reader findings were fixed at the
source in opencharly/charly#309.

**The damaging one.** Three copy-pasteable `charly ollama` commands hardcoded
`--server http://127.0.0.1:11434`, and a fourth line told the reader to curl `localhost:11434`.
11434 is the port INSIDE the container. A deploy can publish it elsewhere and a check bed
allocates the host port automatically, so a reader copying those commands on any bed-allocated
deploy gets a connection refused — with nothing on the page to explain why, and a sibling page
already stating that the host port is read from `charly status`.

The commands now read the `Ports:` line from `charly status ollama` first, and the page says
plainly that the flag is droppable only where the deploy publishes 11434 unchanged.

**An intermediate version of this fix was itself fabricated**, and review caught it. It told the
reader to read a "PORTS column" showing `<host>-><container>`. Neither exists for that command:
`charly status <box>` takes the DETAIL path (`candy/plugin-status/command.go` — a non-empty box
argument reaches `RenderDetail`; the PORTS column lives in `RenderTable`, which only the bare
`charly status` reaches), and no renderer emits `->` — `longPorts` formats `HOST:CONTAINER/proto`.
Verified against a running deploy rather than from the source alone:

    $ charly status check-fedora-coder-pod
    Ports:     38681:2222/tcp, 43887:18765/tcp

So the page shows that line and points at the left of the colon.

Worth recording because the first fix was worse than the defect: it used
`charly status ollama --format json | jq -r '.ports[]…'`, which violates R4a — every command a
reader is told to run must work with nothing but the `charly` binary installed, and naming `jq`
makes the page depend on a tool it never introduces. `charly status` already prints a PORTS
column.

**The wildcard.** "The `ollama` BOX lives in a `box/<distro>` submodule" is a forwarding address
a reader cannot follow: `<distro>` is a placeholder, so a page that has just declined to state
the composition points at nothing specific. It now names `box/fedora` and `box/cachyos`.

Projection only — the prose lives on the candy.
