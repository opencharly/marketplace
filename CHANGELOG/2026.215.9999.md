# 2026.215.9999 — `git add` is all-or-nothing: the rename+edit staging trap

Third occurrence in this program of one mechanism, in two shapes. A single `git add` whose
pathspec includes a path that no longer exists fails the **whole** add — `fatal: pathspec '<old>'
did not match any files`, exit 128, nothing staged, including every path that did resolve.

| Shape | Prior command that staged something | What lands |
|---|---|---|
| deletion | the deletion was pre-staged | only the deletion — a broken partial commit |
| rename + content edit | `git mv old new` staged the rename | the rename, with the content edit dropped |

The rename shape produced this repo's `CHANGELOG/2026.215.1609.md`, whose filename was finalized
to the merge-time CalVer while its heading line still read `# 2026.215.9999 — …`.

## Why the existing invariant did not catch it

`/charly-internals:git-workflow` already carried "Post-commit staging verification": re-run
`git show --stat` and confirm every intended file is listed. **The rename shape passes that
check.** Reproduced in a scratch repo:

```
$ git mv old.md new.md && printf '# 1609 heading\n' > new.md
$ git add old.md new.md
fatal: pathspec 'old.md' did not match any files      # exit 128 — nothing added
$ git status --short
RM old.md -> new.md                                    # looks exactly as expected
$ git commit -m x                                      # succeeds
$ git show --stat
 old.md => new.md | 0                                  # the file IS listed
$ git show HEAD:new.md | head -1
# 9999 heading                                         # the edit was dropped
$ git status --short
 M new.md                                              # the edit, still unstaged
```

Presence in the `--stat` list is not the signal. The tells are the **magnitude** — `| 0`, zero
insertions on a commit meant to change content — and the **leftover ` M <new>`** afterwards.

## The rule added

Stage a rename+edit as `git add <new>` alone, or `git add -u`; stage a deletion by directory or
with `git add -u`. Never name a vanished path. Re-read `git status --short` after any `git add`
whose exit code went unchecked, and read the numbers in `git show --stat`, not just the filenames.
