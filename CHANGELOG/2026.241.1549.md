# 2026.241.1549 — feat: generate from this repo's refs list, not from a charly checkout

## Summary of changes

Phase C of the candy de-submodule cutover: **the refs list in this repo becomes the one generation
input.**

The workflow used to clone charly, copy this repo's refs list **into** that checkout, and run
`generate --root /tmp/charly`. Both reasons for that are gone:

- charly's `candy/` dirs owned in-repo skill entities (`charly-build`, `charly-check`, …);
- charly carried its own **stale** copy of the refs list, which had to be overwritten before every
  run.

The cutover moved every candy into its own repo and emptied `charly/candy/` entirely
(`opencharly/charly#457`), so a charly checkout now supplies **no entities at all**.

| Change | |
|---|---|
| `--root` | now **this repo** — `candy/charly-marketplace/charly.yml` is the authoritative refs list, and every `skill:`/`hook:` entity resolves transitively from it |
| `mkdir -p` + `cp` of the refs list into `/tmp/charly` | **deleted** |
| the charly clone | drops `--recursive` — `box/*` was only cloned because `--root` used to be that checkout and `candywalk` walks `box/<distro>` |

## What the charly clone is still for

Stated in the workflow rather than left to be rediscovered: it **builds the binary**, and the
`cd /tmp/charly` is what puts the `marketplace` **command word** into the CLI grammar.

I measured this rather than assuming it — **my first attempt dropped the `cd` and failed exactly
there**:

```
$ cd <marketplace> && /tmp/charly/bin/charly marketplace generate --root . --out .
Usage: charly <command> [flags]          # the GENERIC usage
exit 80
```

`marketplace` is an out-of-tree command plugin, and the word only registers when charly runs inside
a project whose prescan declares it. This repo declares no such candy.

Fixing that means giving this repo a root `charly.yml` declaring the word — which needs a **local
plugin shim**, because a remote candy ref does **not** register a command word (also measured, on
the `generate-packages` probe: a project pinning only `@github.com/opencharly/plugin-generate-packages/…`
exits 80). That would add the first Go module to this repo, so it is **Phase C.2 and kept separate**
rather than folded in here.
