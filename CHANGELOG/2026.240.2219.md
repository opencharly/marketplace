# 2026.240.2219 — chore(refs): bump charly to v2026.240.2158 + regenerate (drops the internals stdio github MCP)

## Summary

Bumps the CI-time charly tag from `v2026.238.1242` to `v2026.240.2158` and
carries the regenerated corpus — the shape `deploy.yml` requires:

> a marketplace PR must bump the charly CI-time tag and carry the regenerated corpus

The bump brings in two merged changes:

- **opencharly/charly#426** → `pod-charly-hooks` `v2026.240.2141`
  (opencharly/pod-charly-hooks#2), which removed the `internals` plugin's
  **stdio** `github` MCP server. `charly-internals` ships no pod, and no candy
  installs `github-mcp-server`, so the server failed to start on *every* session
  on any host lacking that binary — while duplicating the `gh` CLI that
  `/charly-internals:git-workflow` already mandates. The four remaining
  `mcp_servers` declarations are `type: http` endpoints served by the pod each
  plugin ships; those are correct by construction and untouched.
- **opencharly/charly#425** → a new section in the `skills` skill on auditing
  skill **delivery** (a corpus can be entirely valid and still never load).

## Rulebook compliance

- **R1 — RCA every anomaly.** The removed MCP server was root-caused (no pod to
  serve it; an undeclared host binary) rather than papered over, and the four
  legitimate pod-provided servers were explicitly distinguished instead of being
  swept up with it.
- **R3 — No duplication.** The removed declaration duplicated the `gh` CLI path.
- **R4 — No workarounds.** The corpus is regenerated by the generator at a real
  merged tag; no artifact was hand-edited, and the `DO NOT EDIT` banner on
  generated files is respected.
- **R5 — Delete legacy completely.** Artifact, manifest key, and description
  clause all go in one commit.
- **R6 — Git safety.** `gh pr list` preflight across every affected repo;
  `chore/` branch, no force-push, no hook bypass, no direct push to `main`. A
  stash/pop round-trip during preparation silently dropped the `deploy.yml` edit
  (the known mixed add+rm hazard); it was caught by re-reading `git status`
  before committing, re-applied, and the stale stash dropped — the committed
  tree carries the bump, as the `deploy.yml` hunk above shows.
- **R7 / R10 — Prove the gate, not the plan.** `task skills:drift` pasted above,
  run on the final committed tree, with the artifact-count delta and the
  tag-vs-main equivalence check as independent corroboration.
- **Pin discipline.** `v2026.240.2158` is a merged, tagged ref on `charly` `main`
  (`ffdae115`, "chore(refs): bump pod-charly-hooks to v2026.240.2141 (#426)"),
  never a PR branch.
