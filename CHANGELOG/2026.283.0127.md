# 2026.283.0127 — fix(watch): enumerate the check-run conclusions — a CANCELLED run read as PASS on a BLOCKED PR (#442)

## Summary

`opencharly/marketplace#442`. The watcher that exists to **name** the POISON state read a `CANCELLED` check run as `PASS`.

Measured on `opencharly/opencharly#460`: it reached `## Review — PASS` with native auto-merge armed and did not merge. Its head carried two same-name `validate / validate` runs — `success` (newer) and **`cancelled`** (older) — and `gh pr checks` rendered the pair as `fail`.

The classifier tested **`=="FAILURE"` and nothing else**:

```bash
| if   ($newest.conclusion|ascii_upcase)=="FAILURE" then "BLOCKED"
  elif any(.[]; (.conclusion|ascii_upcase)=="FAILURE") then "SUPERSEDED"
  else "PASS" end
```

On that head both branches were false, so the fall-through was **`"PASS"`** — and the script's contract for `PASS` is *"newest completed is SUCCESS, no failure → keep polling (await merge)"*. **On a PR that was `BLOCKED` and could never merge, the sanctioned watcher said "awaiting merge" until its timeout: the silent stall it was written to remove, reintroduced one conclusion value to the left.**

## The change

**The conclusion vocabulary is ENUMERATED, never inferred.** `blocking` is a predicate over the API's own set — `FAILURE`, `CANCELLED`, `TIMED_OUT`, `STARTUP_FAILURE`, `STALE`, `ACTION_REQUIRED` — with `SUCCESS`, `NEUTRAL` and `SKIPPED` as the passing values. **A conclusion the list does not know is not assumed to pass**, which is what the old `=="FAILURE"` test did by construction.

The SUPERSEDED report also stops naming `FAILURE` specifically: the superseding run may have failed, been cancelled, or timed out, and the message now says *"an older non-passing run … is superseded by a newer SUCCESS"*.

## How tested

`scripts/watch_family_test.sh` — the repo's own offline stub-`gh` suite — now carries **8g-bis**, which feeds exactly `#460`'s payload (a newer `success`, an older `cancelled`) and asserts the watcher **must not** report PASS and **must** name the superseding class.

```console
$ bash scripts/watch_family_test.sh          # with the change
ok   - pr_state_watch: a CANCELLED run beside a newer SUCCESS is NOT read as PASS
PASS — all watcher-family assertions passed                   rc=0

$ # with the classifier mutated back to FAILURE-only:
FAIL - pr_state_watch cancelled+success
       read a CANCELLED run as PASS: 01:13:08  opencharly/x#1  PASS  verdict PASS at head
       abcdef123; awaiting merge (mergeState=BLOCKED)         rc=1
```

**The coverage fails without the change, on the real shape** — and the mutated run's own output is the defect in one line: **`verdict PASS … awaiting merge (mergeState=BLOCKED)`**. It reported an armed, awaiting merge, and simultaneously printed the merge state that proved it was not.

## What this does not claim

It does not claim `SUPERSEDED` is a *terminal* verdict — it keeps polling, by design, because a superseded run sometimes settles on its own. What it claims is narrower and was measured: **a non-passing conclusion is no longer reported as a pass**, so the watcher can no longer describe a blocked PR as merely awaiting merge. Whether a superseded run that stays `BLOCKED` deserves its own actionable verdict (the REST re-run that actually cleared `#460`) is a real follow-up, not asserted here.
