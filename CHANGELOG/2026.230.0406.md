**Guard 1 also failed a case this page calls correct.** It treated `UNMERGED` as failure, while the
discriminator table further down the page says *"this entry's own diff — present tense is right."* An
entry citing its own open branch is legitimate, so that case was unsatisfiable while the source PR
is open. `UNMERGED` is now information the reader judges; `UNRESOLVED` — a citation nobody can check — and `UNCHECKED` set a nonzero exit.

**And the guard wrote "could not check" out as a verdict.** `merge-base --is-ancestor` returns
**128**, not 1, when `origin/main` is unresolvable — a pruned remote-tracking ref, a fresh clone, a
repo whose default branch is not `main`. A bare `&&`/`||` cannot separate 128 from 1, so the guard
printed `UNMERGED`; and because this same cutover made `UNMERGED` non-failing, **the run exited 0**.
A `2>/dev/null`, present since the round-2 fix, hid the `fatal:` that would have shown it.

**That violates a rule this project already publishes** — *"Capture `rc` and
classify it: `0` ancestor, `1` not, anything else not a verdict."* `rc` is now captured and
classified; `UNCHECKED` sets a nonzero exit.

**Every empty case now says so.** `grep` exiting 1 on no matches had made *found nothing*
indistinguishable from *never ran*, in the guard that greps for exactly that class of claim.
