# 2026.327.1501 — feat(corpus): retire pod-immich-ml and regenerate the corpus

## Summary

The published corpus stops publishing the retired `pod-immich-ml`. Immich's ML backend lives in the single `immich` image since v3.4.2 (opencharly/pod-immich), and the separate ML pod is archived — but the corpus kept republishing its skill because stale subpath pins in `pod-dsh` and `layer-agentteams` still reach old `distro-*` trees whose box manifests compose it (measured chain and the two rejected structural rules: opencharly/plugin-marketplace#63).

This PR, in one cutover:

- **Adds `retired.cue`** at the corpus root — the corpus's retirement list, validated by the generator against its closed `#Retired` CUE definition:

  ```cue
  retired: [
  	"github.com/opencharly/pod-immich-ml",        // the archived ML pod
  	"github.com/opencharly/layer-charly-immich",  // drained carrier whose old tags still carry immich-ml-layer
  ]
  ```

- **Deletes the surviving pin** `pod-immich-ml:v2026.314.0717` from the refs list. It was still there on `main`; the retirement list turns a lingering pin into a hard generation error, which is exactly how this PR found it (the first run failed with `the refs list pins retired repo(s)` before writing anything).
- **Advances the generator pin** `opencharly/plugin-marketplace` `v2026.319.1409` → `v2026.327.1351` (its retirement-aware release), and the generation shim's module (`tools/marketplace-cli/go.mod` + `go.sum`) to `candy/plugin-marketplace/v0.2026327.1351`, which carries `sdk v0.2026327.1226` and `spec v0.2026327.605`.
- **Regenerates the corpus** from that toolchain and compares the published skill set with `origin/main`: exactly two removals — `immich/skills/immich-ml` and `immich/skills/immich-ml-layer` (the latter's body composes the retired pod, a live dangling address); `.well-known/skills/index.json` drops the entries; nothing else moves.
- **Documents `retired.cue`** in `AGENTS.md` (as hand-authored, and as the reason removing a pin alone is not enough).
- Is rebased on upstream `main` (after opencharly/marketplace#642) and carries **only** this change: no pin refresh rides along, so it cannot race the daily refresh.

Completes opencharly/plugin-marketplace#63 (the generator mechanism merged as opencharly/plugin-marketplace#65; this PR is the data + regeneration that removes the symptom). The plugin repo's follow-up bumps `MARKETPLACE_REF` to this PR's merge head so its generator-side drift gate compares against the new corpus.
