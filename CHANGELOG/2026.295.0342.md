# 2026.295.0342 — fix(scripts): the `files` rule reads `none`/`nothing` as the negative claims they are

## Summary

The fresh `charly/pr-validator`'s `PASS` on `opencharly/marketplace#526` carried four
non-blocking observations. Two of them were defects in a control this change depends on,
and they are fixed here. One is filed with its RCA, because fixing it is a redesign of the
rule rather than a patch to it. One is a wording slip in a body that is now changelog
history, and history is not edited.

**Fixed 1 — the negation vocabulary decided the polarity, and `none`/`nothing` were
missing from it.** `scripts/pr_body_lint.py`'s `files` rule compares what a body says
about a file with what the same body says about it elsewhere. Which way a claim points
is decided by the words around it — and the vocabulary that decides it did not carry
`none` or `nothing`. So "the `cutover-policy` skill carries none of the new grammar" was
read as a **positive** claim, while "the same file does not carry the new grammar" was
read as a negative one. A body that said the negative in both phrasings was therefore
read as claiming **both** directions about one file, and the rule fired on a body that
was telling the truth. A lint that cries wolf on a true body teaches authors to ignore
it, which is the one outcome a linter must not have — and this rule was written for the
`files` class precisely because that class needs a mechanical comparison.

**The vocabulary is now ONE list, read in TWO positions.** The words that decide a
claim's polarity live in a single `NEGATION_WORDS`, read before the predicate (a negative
subject — "X does not carry the new grammar") and immediately after it (a negative
object — "X carries none of the new grammar"). The two positions differ in **where** they
look, not in **which** words they recognise, and that is the point: the list had drifted
into two copies, and the copy behind the predicate was the narrower one. A second copy of
a vocabulary is how two copies drift apart, so there is now one.

**Fixed 2 — the calibration was a sample where it should have been the whole corpus.**
The suite asserted the rule against 25 merged bodies; the wider run across the five
repos of the coordination cutover was a manual one. The suite now scans **every** merged
body this repo carries in its own `CHANGELOG/` — 424 entries today, each one the body of
a merged PR written at merge time — and it fails if that corpus shrinks below 400
entries. The calibration is therefore asserted on every run of the suite rather than on
every run of a script somebody has to remember.

**Filed — a paragraph that mixes polarities is not compared at all.** The rule works per
PARAGRAPH, and a paragraph is compared only when all of its claims share one polarity.
That guard is load-bearing: the claims of a paragraph are attributed to every file the
paragraph names, so "A carries the change while B does not" carries a positive claim
about **B** too, and comparing them would report a contradiction the body never made.
The cost is the mirror image — the paragraph is not compared, so a contradiction it may
really contain is invisible. Fixing it means binding each claim to the file it is
**about** rather than to every file the paragraph names, and that binding needs
narration detection to keep the round-3 false positive out. That is a redesign of the
rule with its own calibration, so it is filed with its RCA as
`opencharly/marketplace#527` and claimed, not half-landed here.

**Dispositioned — "hunks" where the body classified files.** The round-4 body said "Two
of those hunks are carried prose" over a table that classifies files. The count it named
is right, and the `counts` rule compares that count against the body's own table
regardless of the noun the body used. The body is now the changelog entry for #526, and
history is not edited.

**Two tests, and what each one proves.** The **change-proof**: the vocabulary is one
list, so a body that says the negative in either phrasing is read as negative in both,
and the positive/negative pair about one file still fires — a fix that silenced the rule
would fail here. The **boundary guard**: the rule compares a body's two statements about
one FILE, and it compares the CLAIMS, so a statement whose object does not name the
change is not a claim about it. "X carries the new grammar" and "X carries none of the
old grammar" are two statements about one file, but only the first names the change, so
the pair is not a contradiction — and the test pins that boundary, so widening the
change-object vocabulary would turn it RED. This guard held before the change too (the
object check runs before the polarity check), and it is here because the validator named
the residual risk and a boundary with no test is a boundary that moves.
