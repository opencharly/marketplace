# 2026.215.1207 — Skills for the opencharly.ai docs site, and an R1 fix to the layer skill

Documentation-only cutover accompanying the opencharly.ai documentation site: two new command /
candy skills, published-surface notes on the two skills whose subject matter the site now
exposes, and the removal of a documented field that does not exist.

## New skills

- **`/charly-build:docs`** — the `charly docs generate` verb: its RUNTIME (out-of-process)
  placement and why a dev-time generator is deliberately absent from `compiled_plugins:`, the
  `GOWORK=off` build note that follows from that, the four generated trees, the
  regeneration-is-a-no-op drift gate, the defined-not-default-active catalog rule, the
  cross-reference rewriting with its three guards, and a plain statement of the one thing the
  generated CLI pages do not assert (command parenthood, which is a Go method rather than a
  manifest field).
- **`/charly-tools:docs-site`** — the Astro/Starlight toolchain candy and the `check-docs` bed,
  including why the candy clones the published docs repo instead of reading the sibling `docs/`
  submodule, and the ordering consequence that follows.

## R1 — `directory:` documented but nonexistent

`/charly-image:layer` carried a full section on a `directory:` field ("where the layer's config
files live") with a worked example, resolution rules, and the claim that `charly box validate`
fails when it points at a missing path.

**That field does not exist.** It is absent from `spec/schema/candy.cue`, from the generated
`spec/spec/cue_types_gen.go` types, and from the loader; no candy in the tree uses it; and
`charly box validate` rejects it outright as `field not allowed`. It was found the direct way —
by authoring a candy that used it, on the strength of the skill, and watching validation fail.

The section is replaced with what is actually true: a candy's relative file references resolve
against the directory containing its charly.yml, the boundary is *enforced* (a `copy:` source
containing `..` is rejected at validate time), and content living outside the candy's own
directory is fetched at build time instead. The R5 sweep found and fixed one sibling claim — the
canonical compact-form example still showed `directory: .`, which would now fail validation — and
one stray mention in the opening paragraph's field list.

## Published-surface notes

The site publishes both the skill corpus and every plugin's declarations, which turns two
previously-internal conventions into public contracts:

- **`/charly-internals:skills`** — a skill's frontmatter `description:` is now a page subtitle,
  and a dangling `/charly-<plugin>:<skill>` cross-reference now BREAKS THE DOCS BUILD rather than
  rotting silently. Renaming a skill means sweeping its references, and the build enforces it.
- **`/charly-internals:plugin`** — a plugin's `providers:`, `schema/*.cue` and `description:` are
  what its public page is rendered from, and its placement is COMPUTED from `compiled_plugins:`
  membership rather than transcribed, so placement must never be written into description prose.
