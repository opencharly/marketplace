# 2026.230.2355 — the ollama GPU claim says what it means

`charly#309` corrected two candy `description:` strings that told a cold reader
something false, and this is their projection.

Both said GPU support is "composed outside" / "never by this candy" without
qualification, on the same published pages that also state a tarball distro gets
one upstream archive which already contains the CUDA backend. A reader who
believed the first sentence and then read the second had no way to reconcile
them, and the reading that a plain-tarball image is CPU-only is simply wrong.

The corrected wording separates the two claims that were being conflated: what
the candy DECLARES (no GPU dependency — true on every distro, and the reason the
backend candies exist) from what an image CONTAINS (packaged distros are
genuinely CPU-only until `ollama-cuda`/`ollama-rocm` is composed; tarball distros
ship CUDA inside the archive regardless).

Regenerated from the candy sources by `charly marketplace generate`; no
hand-editing.

## Two body defects the validator's cold reader found, fixed at the same source

The same review that blocked this PR ran a cold reader over the finished pages, and it found
two things the front-matter fix did not touch — both in the `ollama` page BODY, both projected
from the same candy:

- The page told the reader to read "the table" as what a packaged build costs on disk. There
  is no size table on that page; the two figures are bullets, and the page's only tables are
  Box Properties, Ports and Volumes. A reader looking for a table found three that do not
  contain the number they were sent for.
- It said `ollama-rocm` is Arch-only, then two bullets later named `box/fedora` and
  `box/cachyos` together as where the composition is decided — sending an AMD reader to a
  distro where the candy cannot work. The corollary the page had left implicit is that BOTH
  backend candies package only on Arch, and that off Arch they DIVERGE: `ollama-cuda` degrades
  into an assertion that the tarball's bundled CUDA is present; `ollama-rocm` has no tarball
  path at all.

## Retraction — the composition attribution in the entry above was FALSE

The paragraph above originally ended by naming which boxes compose which backend, and cited
`box/fedora/box/ollama/charly.yml` as having been checked. `docs#82`'s validator falsified it: at
the gitlinks the source branch pins — which are those repositories' `main` — NEITHER distro
submodule composes EITHER backend candy, and the strings occur nowhere in either repository. The
composition exists only on the UNMERGED `feat/ollama-plugin` branches of `distro-fedora#18` and
`distro-cachyos#15`; the check that "verified" it read a `box/fedora` working tree still sitting on
that branch rather than at the pin.

The enumeration is deleted rather than corrected, at the candy source. Naming boxes on that page
was itself the defect — the list lives in the distro submodules, moves there, and any copy on the
ollama page is stale the moment one of those PRs lands, so a corrected list would have been wrong
again within a day. The page now carries only the part that does not move: both backends package
on Arch alone, and off Arch `ollama-cuda` degrades into an assertion while `ollama-rocm` has no
path at all.
