**1. `coord.sh` named the wrong half of the command line (#411).** The positional parser
had three slots (verb, target, anything else) and one catch-all message:
`die "unexpected argument: $1"`. A two-word verb written unquoted — `coord.sh TAKING OVER
repo#1` — is split by the shell, so the verb slot takes `TAKING`, the **target slot**
takes `OVER`, and the repo ref the caller typed *correctly* lands in the catch-all. The
diagnostic therefore blamed the one argument the caller had written right. Two changes:

- the `<VERB>` usage paragraph now states that the verb is **one argument**, with both
  working forms and the failing form side by side;
- the catch-all recognises the shape and names the real mistake — the two-word verb that
  needs quoting or an `_`/`-` spelling — while a genuine extra argument still gets the
  generic message (scenario F).

**2. Running this repo's own scripts left the tree dirty (#412).** `scripts/` is
Python-adjacent (`pr_body_lint.py`, `squash_body.py`), and importing either writes
`scripts/__pycache__/squash_body.cpython-314.pyc`. Nothing ignored it, so a contributor
who ran the repo's own linter — the exact thing the PR workflow asks them to do — ended up
with a dirty tree carrying an untracked binary blob. `.gitignore` gains `__pycache__/` and
`*.pyc`, appended after `bin/` so the syncthing-conflict group above it stays intact.

### 3. What the BLOCK found, and what changed for it

The `charly/pr-validator` run on the previous head (`022ec1c`) returned **BLOCK** with two
findings, **both against this PR's own new code, not against the diff's intent**. Both are
fixed here, in one commit:

- **R3 — the normalisation was duplicated, not shared.** The new diagnostic re-implemented
  `tr '[:lower:]' '[:upper:]' | tr '_-' '  ' | tr -s ' '` inline, next to the validation
  path's own copy, so the two could drift into different notions of "the same verb". This
  was a fair hit: the previous body *claimed* the diagnostic derived the first word from
  the same normalisation the validation path uses, and the diff did not back that claim.
  Both call sites now call **one `canon_verb` helper**, which also trims the outer spaces
  the `_`/`-` mapping can produce. `grep -n "tr '_-' '  '" scripts/coord.sh` returns exactly
  one line — inside the helper.
- **R10 — the new code shipped no test that would FAIL without it.** Also fair: the suite
  passed with *or* without the new branch. `coord_test.sh` gains **twelve assertions** — three
  invocations of a shared `assert_two_word` helper, four assertions each (the exit-2 `eq` plus
  the three `grep` checks on the message) — covering both two-word verbs and a lowercase split
  that reaches the label only through the shared normalisation.

No behaviour change on any correct invocation: the canonicalised label is identical for
every accepted spelling (scenario D).
