# 2026.226.1030 — record that the PreToolUse gates are unwired in Claude Code

The plugins leg of the superproject's hook-unwiring cutover (charly#264). Eight
skill surfaces asserted that `pre-commit-gate.sh` / `pre-push-gate.sh` fire as
Claude Code `PreToolUse(Bash)` hooks, or that they mechanically block commits
under this harness. `.claude/settings.json` wires no hooks, so under Claude
Code they fire on nothing — while remaining live in `.reasonix/settings.json`
and in `~/.kimi-code/config.toml`, which delegates to `.claude/hooks/`.

The trade is stated accurately, because an earlier revision of this entry was
not: both scripts DO block what they exist for. Measured directly — `git commit
--no-verify`, a `core.hooksPath` override, `git push --force` and a direct push
to `main` each exit 2 with a BLOCKED message, while a non-git command exits 0.
This removes a WORKING local backstop; it is not a no-op cleanup. What is
accepted in exchange: the hooks ran before every Bash tool call to catch a
narrow set of git invocations, and most of the discipline they encode is judged
for every harness by the fresh `pr-validator` at merge and by branch protection.
The exception, stated plainly because it is a real loss: branch protection
covers `main` alone (no rulesets, no other protected branch), so a `feat/`
branch force-push — which the rulebook forbids everywhere — now has no
server-side block under Claude Code, and the validator cannot substitute since
it inspects a branch already rewritten. Under this harness the agent is the
enforcement for those mechanics.
