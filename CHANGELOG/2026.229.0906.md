## The review rounds the block earned

**What the first version did**, and what a `pr-validator` held it for: a defect of exactly the class
the block exists to fix. Its four runs numbered 3 and 4 **asserted** their state in `#` comments
where the block's own banner promises a paste. Run 3 claimed a regeneration whose `charly
marketplace generate` appeared nowhere on the page, and run 4 asserted `git status --porcelain`
empty without running it — twenty lines after the same block establishes that drift-clean and
git-clean are *independent claims*. The six-run form described above is the repair.

Three additions came out of that round, each measured rather than reasoned:

- **`(stale)` marks the ORPHAN and reads backwards** — the genuinely out-of-date artifact gets no
  suffix; the file projected by nothing gets it. Both directions print the same "are stale"
  headline, so the suffix is the only discriminator, and it names the rarer case.
- **The ` m` / ` M` submodule discriminator holds only under `--short`.** `--porcelain` collapses
  both states to ` M`, so the script-safe spelling is the one that loses the distinction.
- **`charly version` identifies the COMMIT a build was made at, never the bytes compiled.** The
  stamp comes from HEAD's timestamp by design, so a dirty-tree build reports its HEAD's CalVer — as
  the block's own first draft did.

**A second round found the cost of that repair.** The round-2 text was ADDED without reconciling
what it superseded, so the page told the orphan-scan anecdote twice, 35 lines apart, with a
byte-identical lede — and this entry described two different artifacts in the present tense. Both
are corrected here. The rule that generalises: **an addition that supersedes text is an edit to
that text**, and the sweep for what it replaced belongs in the same commit — in every repo the
change reaches, not just the one where the correction was noticed.
