# 2026.215.1850 — the tutorial-shell recipe card, and the gourmet-kitchen tagline

Two changes, both serving the same repositioning: OpenCharly is **the fully stocked gourmet kitchen
for you and your agents**, and the documented example it teaches from is now a real box with a card
of its own.

## `/charly-distros:tutorial-shell` — new

The recipe card for `tutorial-shell`, the teaching box that opencharly.ai's quickstart and concepts
curriculum quote verbatim. The box lands in `opencharly/distro-fedora` (PR #10); its release CalVer
is finalized at that PR's own merge, so this entry names the PR rather than asserting a version.

The card carries three things a generated reference page cannot:

- **why those three candies** — `ripgrep` teaches a TOOL layer, `sshd` a SERVICE layer (and
  init-polymorphism), `supervisord` the container init. The box stops at three because every
  addition costs a line on several published pages.
- **what the box's own plan asserts, and what it deliberately does not** — its single `check:` step
  covers the wiring composition produces (the service candy became a supervisord program); it does
  NOT re-assert co-residence, because every composed candy's plan already runs against that same
  image and restating it would duplicate the candy (R3).
- **the editing rule** — the site *excerpts* the box, so changing it is a documentation change:
  re-read the pages that quote it in the same cutover, or the quoted block becomes a
  doc-vs-reality divergence (R1).

That last point is why the card exists at all rather than leaving the box to its generated
reference page. Concept 03 on the site claims every piece has a card; a newcomer's first click must
not falsify it.

## Tagline

`README.md` now reads *the fully stocked gourmet kitchen for you and your agents*. The previous
wording described what the project **produces**; the new one states the actual bet — that you hand
an agent everything and secure the boundary, rather than shrinking the toolset.

The `charly-distros` skill count moves 34 → 35 with the new card.

## `pr-validator` — the PR-body attribution footer becomes a checked gate

Three PR bodies in this cutover opened with `*This pull request was authored by an AI agent (…)*`
instead of ending with the mandated `*Assisted-by: <Harness> <Provider Full Model Name>
(<confidence>)*` line — and **neither validator flagged it**.

The cause is locatable rather than a lapse: item **A.3** judges whether the *tier* is earned and
whether harness/provider/model identity is right, and the spec's other footer references govern the
**validator's own comment**. Nothing required the *author's body* to carry the line, so the
requirement lived in the template and the project rulebook with no checklist row behind it.

A.1 now carries an explicit sub-item for the body footer's presence *and form*, and checklist row 1
names it. A gate nobody is asked to check is not a gate.

## `/charly-internals:agents` — invariant 9: a validator moves the author's HEADs

Hit live during this cutover. Validators were spawned while the author still had uncommitted work
in four repos; their W0 base/head binding legitimately checks out the protected base and re-syncs
gitlinks — correct for the validator, destructive for a mid-edit author. The superproject silently
moved from `feat/<slug>` back to `main` and `plugins` detached to the gitlink SHA, while two *other*
submodules stayed on theirs, so nothing looked globally wrong.

The tell is counter-intuitive and is the reason this is worth writing down: **a file you committed
reads with its OLD content while `git status` is CLEAN.** A revert leaves the tree dirty; a HEAD
move does not. Without that cue the natural reading is "my edit didn't save", which sends you
rewriting work that is sitting safely on a branch ref.

Records the avoidance rule (commit and push every repo before spawning a validator; stop it once it
has posted) and the one-loop check to run afterwards. Invariant count 8 → 9, swept in the `SKILL.md`
index row too.

## Scope

Documentation only — every file in the diff is `*.md`. Beyond the new card it changes **two guidance
surfaces**: the `pr-validator` agent spec (a new gate sub-item, strictly additive) and the
`/charly-internals:agents` skill (invariant 9 plus its count sweep). No rule text was moved between
owners, and no existing gate was removed, narrowed or softened.

The superproject's `README.md`, `VISION.md` and `CLAUDE.md` carry the matching tagline change; the
`opencharly/docs` site carries the landing page and the twelve-part concepts curriculum that quote
this card's box.
