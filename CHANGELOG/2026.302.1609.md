# 2026.302.1609 — feat(lint): the bang arm relates the head's marker to the body's answer

## Summary

Head `0269c2fdf4f5cfc0d28c6521011ab041973401d4` — the commit this PR pushes: **2 files changed, 256 insertions(+), 6 deletions(-)**

**The org's body linter checks the body's FORM and never reads the head's SUBJECT.** So the relation the org's own rulebook settled — the subject's Conventional Commits `!` marker and the body's `**Breaking change + rollback:**` answer are two halves of ONE question — was mechanically checkable in exactly ONE repo, and every other repo's PR body was judged without it.

**The rule is already PUBLISHED.** opencharly/opencharly#805 stated it in the umbrella's `AGENTS.md` (line 432), in its `git-workflow` skill (the section at line 138) and in its `cutover-policy` skill (line 138), and this repo's corpus projects those two skill bodies from the umbrella's pinned source (`@github.com/opencharly/opencharly:v2026.302.1338`) — byte for byte, apart from the generator's own two-line `DO-NOT-EDIT` header (item 7 below). So every consumer of the corpus can already read the obligation.

**What no consumer could MEET was a machine check of it.** This repo's `scripts/pr_body_lint.py` is the org-wide linter: the umbrella's `scripts/check-pr-body-gate.mjs` runs it, the umbrella's `hooks/pre-push` and `hooks/pre-commit` run it, and this repo's own generation workflow runs its test. No other repo's CI invokes it — opencharly/sdk's `ci.yml` does not — so the arm's mechanical reach today is those gates, and none of the linter's rules ever reached the commit's subject line.

This PR gives it the relation.

**The arm.** `scripts/pr_body_lint.py` gains a `bang` rule:

- it reads the head's SUBJECT — `git log -1 --format=%s <head>`, in `--repo`;
- only the Conventional Commits HEADER is read, the part before the first colon, because a subject's prose may carry a colon and a bang of its own (`docs: correct the 2026.299.0822 entry's false clause about the FAIL: marker` is a documentation fix, not a cutover), and the marker sits at the END of that header, where Conventional Commits puts it (`feat(scope)!: …`);
- under a marker, the body's `## Change classification` MUST carry a `**Breaking change + rollback:**` line, and the answer's value is what follows the first colon after that key;
- a bare `none` is refused — "none — the pointers move to commits the org has already merged" is an answer, "none" alone is not;
- the mirror direction is NOT implemented: a body that declares a breakage without the marker is legal, and the marker is never inferred from the line;
- when the subject cannot be read, the rule SKIPS, visibly — a lint that invents the truth is worse than a lint that stays quiet.

**The bare-`none` half is prophylactic, and the measurement says so.** The shape it forbids — a marker-carrying subject whose answer is a bare `none` — does not exist in the org's merged history. Measured on 2026-10-29 over every opencharly repo's most recently created closed pull requests (474 repos, 4,469 merged pull requests, 2026-07-07 to 2026-10-29): **373 carry a marker-carrying subject, and not one carries a bare `none`.** One carries a reasoned `none` (opencharly/opencharly#801), one carries a real answer (opencharly/spec#208), and the other 371 carry no answer line at all — the SILENCE, not the bare `none`, is the measured defect. The rule has to hold before the first instance, not after it (item 8 below).

**One published number is wrong, and it is FILED.** The umbrella's `git-workflow` skill states this same measurement over its own narrower window and names `opencharly/plugin-box#66` as a body that answers with a reasoned `none`. That body carries no breaking-change answer at all, and the rule the same paragraph states would refuse it. The sentence lives in the umbrella's authored skill body, so it is FILED as opencharly/opencharly#809 and lands with the umbrella's wave — the corpus and the docs site are generated projections of that file and carry the correction when their pins advance, never by hand.

**One consequence, FILED.** The umbrella's own reconciler carries a SECOND implementation of this rule — arm M in `scripts/check-pr-body-diff.mjs` — because the rule's home repo had to carry the mechanical check before the org-wide linter could arm it. That is R2 — one canonical implementation or rule per behavior — and it is genuinely separable from this change: this arm is correct and complete without it, and the umbrella's copy is a different repo's to remove. So it is FILED as opencharly/opencharly#808, not fixed here.

Closes #603.
