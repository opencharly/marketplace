# 2026.285.2307 — fix(refresh): one classified publication attempt with a readback, and current rulebook numbering (marketplace#451)

## Summary

The nightly refs-refresh published its PR with a **blind retry loop**: `for attempt in 1 2 3 … sleep $((attempt * 10))` around `gh pr create`. It **repeats a write**, and repetition cannot make a write safe — a 504/5xx may mean the PR was created and only the *response* was lost, so the next attempt fails with "already exists" and **masks the success**. It is now **ONE attempt plus an idempotent READBACK** that tells three states apart: **published**; **created, response lost**; **not created** — the last one `::error`s with the byte-exact failure, keeps the already-pushed branch (nothing is lost) and prints the by-hand URL. No sleep, no repeat (R3).

The emitted compliance block also carried **retired rule numbering**, so every refresh PR body named the wrong rules. It is re-mapped to the current rulebook and now emits, in order, one bullet each with its own body: `R1` (no parking — the corpus edit belongs in the owning repo, which gated it; a defect in *this* workflow is fixed here), `R2` (no duplication), `R3` (no workaround), `R5`, `R6`, `R7` (emitted artifacts — the retired `R8 artifact invariants` folds in here), `R8` (live, not faked — the API calls are real), `R9`, `R10`.

**Round-2 correction (commit 2).** The first commit was built by copying `refresh.yml` from the umbrella's submodule checkout (`ee110b4`) over the newer session-worktree file (`dfea8e5`). Between those revisions `#450` landed the shared `./.github/actions/build-charly` toolchain step, which the older copy lacks — **my copy silently reverted it**, so the diff appeared to swap a shared action for an inline `git clone` + `setup-go@v5` + `go build`. That was an **R6** violation and exactly what the round-1 block named. Rebuilt from `origin/main`'s baseline: the toolchain step is intact at `:62` and the diff does not touch it.

**Round-3 correction (commit 3).** The round-2 rebuild spliced **line ranges computed by hand from two anchors**, and an off-by-one silently deleted the new `R1` bullet's *header* while leaving its two body lines: the emitted block printed a headerless fragment with no rule id right after the log fence — the very class of artifact this PR fixes. The block now emits a complete, in-order rule list, and the harness validates the **emitted** artifact at its boundary by executing it, so this cannot recur.

**Round-4 correction (this body, no code change).** The round-3 body pasted the **round-2** `git diff --stat` under the round-3 head and merged the harness's `PASS` lines with `" / "`. Both are corrected below: every block is now the verbatim output of the command shown, produced at head `230e1140`.

**The row's third ask is NOT implemented, and that is a deliberate, measured decision** — on the row's thread (`6134044454`). It asks to move the 65536-byte body gate **before** the push; the gate exists and its post-push position is documented as deliberate: the push preserves the night's refresh when the body is *deterministically* rejected, and the assembly already elides the generator log to stay under the limit. Moving it pre-push trades a lost PR for a **lost refresh** on an ephemeral runner. The row therefore stays **open** pending the operator's call.
