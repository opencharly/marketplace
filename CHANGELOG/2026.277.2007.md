# 2026.277.2007 — fix(scripts): pr_watch_many must forward teardown to its per-PR watchers

## Summary

`pr_watch_many.sh` starts one long-lived `pr_state_watch.sh` per PR and then **had no way to
stop it**. It records `$!` of the subshell the watcher is started *inside*, so `cleanup()`
killed the wrapper and the watcher survived as an orphan reparented to `systemd --user`
(`#417`). One file's spawn block, plus the assertion that would have caught it:

| file | ± |
|---|---|
| `scripts/pr_watch_many.sh` | +16/-1 |
| `scripts/watch_family_test.sh` | +33 |

### The defect, stated as the mechanism

`( "$WATCH" … ; code=$? ; … ) 9>&- &` cannot `exec` the watcher — three statements follow it,
so `pr_state_watch.sh` is the subshell's **child**. `$!` is the **subshell's** pid, `cleanup()`
kills exactly those pids, and the script's only other stop is `wait`, which waits on
subshells. So the child outlived every exit path — the first-wake exit, the `--all` exit, the
timeout exit, and the `TERM`/`INT` trap — and was reaped by nobody. `9>&-` solves the *flock
fd* problem and does nothing for lifetime. The wrapper's own comment calls the watcher
"LONG-LIVED", which is precisely why it survived.

The consequence is not tidiness. A leaked watcher polls outside every control the family
established in `#373` — the 60 s poll floor, the single batched poll, the rate-limit abort —
so on a shared account it spends the org's API budget invisibly, and it is indistinguishable
from a watcher another session armed on purpose.

### The fix

The subshell runs the watcher in the **background** and `wait`s on it, forwarding our teardown:

```
( "$WATCH" "$repo" "$pr" --interval "$INTERVAL" --timeout "$TIMEOUT" >/dev/null 2>&1 &
  wp=$!
  trap 'kill "$wp" 2>/dev/null; exit 143' TERM INT
  wait "$wp"
  code=$?
  printf '%s|%s|%s\n' "$code" "$repo" "$pr" > "$rp.tmp"
  mv "$rp.tmp" "$rp" ) 9>&- &
```

`TERM` carries teardown (the wrapper's `INT` path re-raises as `exit 143`, so cleanup always
sends TERM); `INT` is set alongside it for the direct-signal case. `wait` also restores the
exit-code propagation `$?` gets from a foreground child.

### One claim in my own issue is retracted

`#417`'s Scope section says "`any_pr_alive` (`:211-216`) needs the same treatment, since it
`kill -0`s the same subshell pids". **That is wrong, and this PR does not touch it.** Once the
subshell *waits* on its watcher, the subshell is alive exactly while the watcher runs, so
`kill -0` on the subshell pid **is** a correct liveness proxy. The over-claim came from
reasoning about the pid while the lifetime was still broken; the fix makes the pid mean what
the function already assumed it meant.

### Bounds, stated plainly

A `TERM` delivered in the one-builtin window between the background spawn and the `wp=$!`
assignment would still leave the child. No path *inside this script* can send a signal there —
`cleanup` runs from the `EXIT` trap, long after the spawn loop has finished — so the window is
reachable only by an external signal landing during the spawn loop itself.

### 3. The new assertion

`watch_family_test.sh` §9b replaces the stub watcher with one that **blocks until killed and
records its own pid**, then drives a run whose only possible outcome is `cleanup` — a TIMEOUT,
so no watcher ever reports on its own — and asserts that pid is gone:

```
ok   - pr_watch_many: cleanup stops the WATCHER (no orphan)
```

The assertion is about the *watcher's* liveness, so it cannot be satisfied by the wrapper
dying. Its failure branch prints the surviving pid and `kill -KILL`s it, so a regression can
never leak a process into the suite's own teardown.

### 4. Mutation control — the assertion fails when the fix is removed

Forward removed (the `trap` + `wait` lines deleted), suite re-run, change restored and verified
byte-for-byte with `cmp`:

```
$ sed -i "/^      trap 'kill …' TERM INT$/d; /^      wait \"\$wp\"$/d" scripts/pr_watch_many.sh
$ bash scripts/watch_family_test.sh
FAIL - pr_watch_many terminal
       TERMINAL MERGED (exit 0) opencharly/x#1
FAIL - pr_watch_many: a TIMEOUT exits 4
       expected [4] got [0]
FAIL - pr_watch_many: cleanup stops the WATCHER (no orphan)
       watcher pid 236144 survived cleanup — it is the wrapper's child, not the wrapper
FAIL — 3 assertion(s) failed        (exit 1)
```

Three failures, and the mix is the point: the new assertion catches the **orphan**, and the two
pre-existing ones catch the **lost exit code** (`wait` is what propagates the watcher's status;
without it `$?` is the background launch's `0`, so the wrapper misreports `MERGED` where the
watcher said `BLOCKED`). Restore verified with `cmp: identical`; `git status --short` then
showed only the two intended modifications.
