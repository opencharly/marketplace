# 2026.243.1643 — feat: project the quickshell skill into the corpus

## Summary

The corpus is generated from an **authored refs list**, not from every repo in the org, so a
skill living in a repo that is not a ref reaches no reader however correct it is.
`plugin-quickshell` was not a ref, so the `quickshell` skill — the guidance for the verb
`check-omarchy-desktop-vm` depends on — was published nowhere.

```
+ '@github.com/opencharly/plugin-quickshell/candy/plugin-quickshell:v2026.243.1637'
```

`plugin-wl` is the precedent, added the same way for the same reason.

### Why this tag and not `v2026.243.1516`

`v2026.243.1516` is the tag the desktop bed pins and was the obvious ref to add. It is the
wrong one to **publish**. `plugin-quickshell#3` landed at `v2026.243.1637` and added the two
things a reader most needs:

- every argument a QML function declares is **required** — omarchy's is
  `summon(pluginId, payloadJson)`, so a panel with no payload of its own still passes `'{}'`;
- omarchy's `summon` returns `"ok"` or `"unknown"` and **exits zero either way**, so a summon
  step with no `stdout:` assertion passes against a shell that summoned nothing.

Publishing the earlier tag would have shipped a skill missing precisely the traps it exists
to prevent.

adding the ref — the only other org match is the candy `layer-omarchy-shell/omarchy-quickshell`,
which is a candy name, not a skill name.
