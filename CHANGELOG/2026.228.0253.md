# 2026.228.0253 — the bootstrap and cloud-init excerpts match what the emitter emits

Regenerated from the superproject candy sources. `opencharly/sdk#138` (merged
`91cc241d`, tag `v0.2026228.209`) shipped **four** fixes, and the published
skills described the pre-fix behaviour for two of them.

## What was false

**The cloud-init sshd start (fix 4)** — three claims said the runcmd carries
`systemctl unmask` + `enable --now` on every distro. On Alpine it carries
`rc-update add sshd default && rc-service sshd start`; there is no ssh.socket to
unmask and no systemctl to enable with.

**The create-mode bootstrap block (fixes 2 and 3)** — four pages printed the
emitted Containerfile verbatim as `groupadd` + `useradd -m … -s /bin/bash`. The
emitter now probes: `LOGIN_SHELL=/bin/sh; [ -x /bin/bash ] && LOGIN_SHELL=/bin/bash`,
then `command -v useradd` with a busybox `addgroup`/`adduser` fallback. Those are
fenced blocks introduced as what the generator produces, so a stale one is an
excerpt-integrity failure, not a wording nit.

Fix 1 (the go-task `curl` → `(curl || wget)` fallback) was already clean: every
page elides that line.

## Why the first sweep missed them

It keyed on the STRING it had just fixed rather than the CLAIM that became
false. Grepping `unmask`/`enable` finds the sshd sites and is structurally blind
to a stale `useradd` block expressing a different falsified claim from the same
commit. Both defects came from one merge; only one had a memorable token.

The corrected key is the claim — *"a doc asserts pre-fix behaviour of anything
sdk#138 changed"* — enumerated per fix, then swept per surface. Two validators
found the gap independently, from different repos, which is what a claim-keyed
sweep would have found in one pass.

## Verification

Every absence check carries a presence control, so a passing grep cannot be a
passing grep over nothing:

- old shape, pattern `useradd -m .* -s /bin/bash`, scoped to `*/skills/*` — **4 files before, 0 after**
  (the looser `useradd -m -u` reads **5 files / 6 hits → 4 / 4** — `distros/debian` carries
  it twice — because the shadow-utils arm survives INSIDE the new branch. The two patterns
  count different populations, and only the strict one measures the defect. Unscoped, the
  strict head count reads 1: this CHANGELOG, quoting the old shape to describe it.
  **Unit stated because it is load-bearing:** a validator and I independently measured the
  loose pattern as 6 and 5, and both were right — hits versus files. An unqualified count
  is the same ambiguity as an unqualified pattern.)
- new shape `LOGIN_SHELL` / `command -v useradd` / `adduser -D` — **0 before, present in 4 candy sources after**
- `charly marketplace generate` from a tree at current `main` with submodules
  initialized touched exactly the 6 intended files, no collateral

## Later rounds — what validation added

The first pass corrected the sshd-start claims and the create-mode excerpts.
Four validator rounds added the rest, and they are recorded here because history
should carry them, not just the opening finding:

- **`pacman -S` → `-Sy`, twice.** Shipped is `pacman -Sy --needed --noconfirm`.
  The `y` is load-bearing — a bare `-S` 404s against a rotated mirror — so a
  reader copying the documented command hit exactly the failure the flag
  prevents. This one PREDATES the sdk change; it was already false on the line
  the sweep was rewriting.
- **The prepend is TWO entries, not one.** An sshd `try-restart` guard follows
  the pacman command, resyncing a live sshd if openssh rode along in the dep
  closure ("hostkeys confused"). It had never been documented anywhere.
- **`base_user:` steers rendering.** Two of its values drive `effectiveDistro`,
  selecting both the package-delivery and sshd-start branches. An Alpine image
  with a custom account name, or an empty `base_user:`, renders `systemctl` onto
  a guest with no systemd and boots unreachable. Now stated as a failure mode
  with its remedy, and `alpine` added to the account list that omitted it.
- **"per-init" glossed at first use.** The term was introduced on new lines in
  both skills without expansion; it now names the guest's init system (systemd
  vs OpenRC) where it first appears.
- **The `|| reboot` fallback.** The guest reboot was documented as
  `(sleep 1; systemctl reboot) &`; the emitter has always written
  `… || reboot) &`. Pre-existing, and INVERTED from every other finding here —
  the page understated the product. A doc that undersells a fallback is how the
  fallback gets deleted by someone who never learned it was load-bearing.

### The lesson that outlived the fixes

Three sweep keys were tried, each finding what the previous missed:

1. **the string just fixed** — blind to a different falsified claim from the
   same commit sharing no token;
2. **the claim that became false** — finds the class, but not claims that became
   merely INCOMPLETE (the `base_user` case), and not falsities that predate the
   triggering change;
3. **re-reading the whole edited paragraph against the source it cites** — the
   only key that finds all of them, because `-Sy` and the missing guard were
   already wrong, on the line being edited, in prose naming its own authority.

A control can also overstate its own rigor: an early "old shape: 0 hits" here
was true only under a `-s /bin/bash`-specific pattern, since a bare
`useradd -m -u` still matches the CORRECTED lines. Every count above is stated
as measured, with its presence control.
