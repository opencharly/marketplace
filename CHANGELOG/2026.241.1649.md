# 2026.241.1649 — fix: the refresh workflow reports the permission it needs

## Summary of changes

The refresh workflow's **first real run** ([33263470985](https://github.com/opencharly/marketplace/actions/runs/33263470985))
did its job — 176 pins read, the refs list bumped, the corpus regenerated, the branch pushed — and
then died on the last step:

```
pull request create failed: GraphQL: GitHub Actions is not permitted to create or approve
pull requests (createPullRequest)
```

**That is a repository setting, not a bug in the workflow.** `gh pr create` from a workflow needs
*"Allow GitHub Actions to create and approve pull requests"*
(`actions/permissions/workflow` → `can_approve_pull_request_reviews`), and it is **off across this
org**:

```
$ gh api orgs/opencharly/actions/permissions/workflow
default=read can_approve_pr=false
```

Deliberately, I think: the same switch **also lets a workflow approve pull requests**, which would
let automation bypass review. **I have not flipped it** — that is a security-relevant decision for
the org to make, not a detail to change in passing to make my own workflow green.

## What this actually fixes: the failure *mode*

The branch was already pushed when the PR call failed, so **no work was lost** — but the run
reported an opaque GraphQL error and said nothing about how to recover. It now prints:

- the pushed branch name,
- the compare URL to open the PR by hand,
- the exact `gh api` call that would enable the setting,
- **and why it is off**, so nobody enables it without knowing it also grants self-approval.

The step order already had this right by accident — push first, PR second. That is now deliberate
and commented, because it is the property that makes a failure here recoverable rather than a lost
night's refresh.
