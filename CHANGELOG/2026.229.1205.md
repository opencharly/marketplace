## What the page now says

**The orphan scan is path-gated.** `scanGenerated` has three arms and only the first reads a file's
bytes: it walks `plugins/<family>/skills` and `.../agents` for the generated header; it adds a fixed
list of known paths on existence alone; it takes every file under `.claude/hooks/` outright. So the
header decides only inside the walked trees, and a header-less file is invisible only when it **also**
sits outside the known paths and the hooks directory — the condition `prune.go`'s own comment states.

**`(stale)` marks the orphan** — a generated path no source claims — not a file behind its source.
Both red directions print the same `are stale` headline, so the suffix is the only discriminator, and
it names the rarer case. `(orphan)` would say it; that message fix is filed as `opencharly/charly#290`
rather than compensated for in prose.

**`git status --short` distinguishes three dirty-submodule states**: ` ?` untracked content, ` m`
modified content, ` M` a moved gitlink — and `--porcelain` collapses **all three** to ` M`, so the
script-safe spelling is the one that loses every distinction. Only ` M` has an ordinary-path meaning:
an untracked ordinary path is `??`, two columns, and lowercase ` m` never appears on one at all.

**`drift` compares every generated artifact**, not only the `plugins/` corpus — the harness surface
(`CLAUDE.md`, `AGENTS.md`, `.claude/settings.json`, `.claude/hooks/*`) is in the same emissions map.
Its reporter lists all but those seven, which is why `generate` prints 400 and lists 393.

**Sweep for every site that NAMES a mechanism, once per repo**, and reconcile each against one
derived ground truth. `git grep` does not cross a gitlink, and this page is projected twice, so a
claim about it lives in three trees that cannot see each other. A string-keyed sweep cannot find the
same claim restated in other words — which is what a correcting author writes in the neighbouring
paragraph.

**The regeneration window.** The projection-first ordering guarantees a period where `plugins/main`
carries prose `charly/main` cannot reproduce. Your own leg's window is harmless; **another leg's is
not**, and the trigger is the base moving under you rather than the existence of a window: run the
unscoped whole-tree check while no foreign projection sits in your base, and scope to the files you
touch once one does.
