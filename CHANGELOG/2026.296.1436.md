# 2026.296.1436 — feat(body-lint): the head rule reads the body's OTHER anchor form too

## Summary

Head `1ce09345be0c32dd0b7b5e318690b0ebd335bf3e` — 3 files, +451 −2.

A PR body has TWO ways of saying which commit its evidence belongs to: the headline `Head: `<sha>`` and a fence that runs `git rev-parse HEAD` and prints the sha. `scripts/pr_body_lint.py`'s `head` rule compared the first against the commit being pushed and never read the second. The two spellings are one claim about one commit, so a body whose fence named a stale commit passed the linter at 0 findings — and the fresh `charly/pr-validator` BLOCKed exactly that body on that drift alone. opencharly/charly#1039 round 1 is the record: the head moved when the commit was amended, the headline was re-pasted, the fence was carried over verbatim, and the linter had nothing to say about it.

This change makes the rule read the second form as well. A bare `git rev-parse HEAD` whose output is a 40-hex sha must print the head being pushed, and a mismatch is a `head-fence:` finding. The command is matched narrowly, so the rule stays silent where silence is right: `git rev-parse HEAD^{tree}` prints a TREE, `git -C <dir> rev-parse HEAD` names ANOTHER repository's head, and a fence that quotes some other commit (an upstream, a predecessor PR) is not this PR's anchor.

The two head findings now print the FULL sha. A finding is evidence, and a body proves a rule by pasting the linter's own output — while the house's `ellipsis` rule refuses a `…` inside a fenced block, so a finding that truncated a sha with one could not be shown in a body at all.

The rule is proved against the org's own corpus rather than a synthetic example: the fixture is the REAL body of the merged opencharly/charly#1039, and the blocked form is that body with its two fence outputs set to the pre-amend commit the validator named.

### The rule does not cry wolf — the org's own merged bodies

Every merged body of the eight repos below is linted against its OWN head, and the new rule is counted separately from the linter's other findings.

```
$ python3 - <<'PY'
> import json, subprocess, sys
> sys.path.insert(0, "scripts")
> from pr_body_lint import lint, head_fence_anchors
> REPOS = ["opencharly/marketplace", "opencharly/opencharly", "opencharly/charly",
>          "opencharly/layer-charly-internals", "opencharly/layer-k3s",
>          "opencharly/layer-nerdctl", "opencharly/layer-docs-site", "opencharly/docs"]
> bodies = fenced = anchors = 0
> findings = []
> for repo in REPOS:
>     out = subprocess.run(["gh", "pr", "list", "--repo", repo, "--state", "merged",
>                           "--limit", "8", "--json", "number,body,headRefOid"],
>                          capture_output=True, text=True)
>     for pr in json.loads(out.stdout or "[]"):
>         b, h = pr.get("body") or "", pr.get("headRefOid")
>         if not b.strip() or not h:
>             continue
>         bodies += 1
>         a = head_fence_anchors(b.rstrip("\n").split("\n"))
>         fenced += bool(a)
>         anchors += len(a)

> print(f"merged bodies linted: {bodies}")
> print(f"bodies carrying a `git rev-parse HEAD` fence: {fenced}")
> print(f"anchors read: {anchors}")

bodies carrying a `git rev-parse HEAD` fence: 14
anchors read: 16
head-fence findings: 0
```
