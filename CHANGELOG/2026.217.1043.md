# 2026.217.1043 — the generator owns the home page, so stop calling it hand-authored

**The docs skill said the home page is hand-authored. It is generated.** `charly docs generate`
gained a landing-page projection (`index.md`, from `README.md`) and a grievances page, and this
skill still described the generator as owning "three top-level trees" while promising that
`index.mdx` "is never read or written". Both sentences became false the moment the projection
landed, and a reader following them would hand-edit a page the next `task docs:sync` overwrites.

The emitted-tree table now carries `index.md` and `grievances.md` with their sources, and the
prose says plainly which pages remain hand-authored — `start/`, `concepts/`, `guides/` — and that
the home page is edited via the README.

Found by a teammate reading the generator against this skill while writing its wiring tests, and
fixed in the same cutover as the change that invalidated it (R1).

Assisted-by: Claude Code Anthropic Claude Opus 5 (documentation reviewed)

Two rounds of this fix shipped their own inaccuracies, which is the point worth recording, because
it is the class the change exists to remove. Round 1's new `grievances.md` row read "same treatment
as the vision page" while the vision row said "`VISION.md` verbatim" — but both emitters drop the
source H1, so the new row inherited a falsehood by reference. Round 2 then rewrote the
hand-authored sentence to "never read or written", and the second half is false on `main` today:
`verifySiteLinks` reads every page under `--out`, hand-authored included, so a dead link in a
`concepts/` page fails generation. The true predicate is never WRITTEN, and the boundary is the
`DO-NOT-EDIT` header rather than the path — which is what the published page at
`docs@979abad:recipes/build/docs.md` already said correctly, and what this round restores.
