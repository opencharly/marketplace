# 2026.240.0810 — fix: remove the charly submodule; clone charly recursively at CI time

## Summary

The candy de-submodule scaffold copied the umbrella structure into every standalone repo, declaring a `charly` git submodule (`path = charly`, `url = https://github.com/opencharly/charly.git`, `branch = main`). The refs downloader's `populateSubmodules` (spec/refs/git.go) initializes EVERY declared submodule on fetch — so a consumer fetching this candy at any ref pulls the ENTIRE opencharly/charly repo into `charly/` inside the fetched tree. That leaked tree breaks the charly parity test (TestFleetCompileParity_PluginRoundTrip): its seedParityProject copies the fetched fixture into .parity/candy/<name>, the .parity root's `discover: candy recursive` walks into .parity/candy/<name>/charly/ finding the ROOT's charly.yml (agentteams box + 663 candy manifests), so cfg.AllBoxNames() returns the root's boxes and the compile resolves "agentteams" instead of the 3 parity fixtures.

**Fix (four parts):**

1. **Remove the submodule gitlink + `.gitmodules`** — the candy repo itself no longer carries any charly tree.
2. **Make the marketplace corpus actually regenerate at the pinned charly tag.** LIVE-PROVEN root cause: the previous deploy.yml's `--root .` pointed at the charly checkout at `v2026.238.1242` (post-cutover), which has only 14 candy dirs and NO marketplace entity — the generate failed with `no marketplace entity found` (exit 1). The fix: the marketplace repo carries `candy/charly-marketplace/charly.yml` — the corpus SOURCE, referencing pod-charly-hooks (the single `marketplace:` entity + hooks) and every standalone candy repo that owns `skill:`/`hook:` entities via `@github` refs — and deploy.yml runs generate with `--root` = the CHARLY CHECKOUT (whose candy/ dirs own the in-repo skill entities: charly-build, charly-check, …) while copying the marketplace's authoritative `candy/charly-marketplace/charly.yml` over the charly checkout's copy.
3. **Rewrite the 40 SKILL.md candy refs to the standalone `@github.com/opencharly/<kind>-<name>:v<tag>` pins** (252 ref lines) — the same Phase-4 residue sweep applied to the corpus's own skill docs, so every documented `candy:` list resolves to the post-cutover standalone repos.
4. **Add the umbrella gate hooks** (`.claude/hooks/pre-commit-gate.sh`, `pre-push-gate.sh`, `gitcmd.py`, `gate_test.py`) + `.claude/settings.json` (enabled plugin catalog) — the deterministic git-workflow mechanics (no `--no-verify`, no force-push, no direct-main, tokenizable commands) that the org's other repos carry, plus the description refresh in `.claude-plugin/marketplace.json`, `kimi.plugin.json`, `package.json` ("Agent-in-the-Loop Factory" → "open infrastructure compiler").
