### Why this PR was opened by hand

The workflow generated this branch and its content correctly, then hit a transient
**HTTP 504** from GitHub's GraphQL API on `gh pr create`:

```
HTTP 504: We couldn't respond to your request in time… Please try resubmitting your request
```

The workflow's push-before-PR ordering is exactly why nothing was lost — the branch was already
safe, and its error output named the branch and the recovery URL. Opening the PR by hand is that
recovery path. A bounded retry for this documented-transient case follows separately, so the next
504 does not cost a run.
