### THE HARNESS CONSTRAINT (the design driver)
An agent is woken **only when a background command COMPLETES**. A never-exiting watcher gives **no wake**; a one-shot watcher that exits leaves **nothing watching** until an agent re-arms. The architecture: **each wake is produced by a finite watcher run, and a successor is already armed before the wake lands.**

### A. `--auto-rearm` (in `_watch_common.sh`, ONE implementation for both watchers)
On any non-terminal exit (a DELTA fire, a TIMEOUT, an unexpected error) the watcher **detaches a lock-guarded successor with the SAME args BEFORE it prints and exits**. `--no-rearm` (the default) is the per-event one-shot.

| Exit | Re-arms? | Why |
|---|---|---|
| DELTA fire (a new `verdict` / `comment`) | **yes** | a watch must survive the event |
| TIMEOUT / unexpected exit | **yes** | a watch must survive a deadline |
| STATE fire (`merged` / `closed` / `stall`) | **no** | the successor would **immediately re-fire** it (a merged PR stays merged) → livelock |
| usage / lock error (5/6), takeover (143) | **no** | nothing to watch |

### B. Durable supervisor is NOT the answer (the headline, stated precisely)
`--auto-rearm` keeps a **watch** alive — it does **not** by itself deliver a wake: a detached successor's event line goes to its log, so **the agent is woken only by the watcher the agent armed**. The two roles are distinct and both are required:

- **the successor keeps the WATCH alive** (a standing observation independent of the agent), and
- **the agent's re-arm keeps NOTIFICATIONS alive** (the next finite run whose COMPLETION wakes the agent).

So the correct headline is **"a watch is always alive with zero dropped re-arm steps"**, not "zero agent involvement". A supervisor that never exits would give no wake at all.

### C. Single-instance lock
A per-args **flock lockfile** (key hashed from the exact args) + a holder PID: repeated arms **never stack**; a foreground arm **takes over** a live peer cleanly. A detached **successor** is marked **`WATCH_INHERITED_LOCK=1`** (a variable `_watch_common.sh` never resets — NOT the run-local `WATCH_REARMED` latch) and **inherits fd 9**: it **already holds the flock** and never waits or re-acquires — the atomic hand-off (see **F**).

### D. Rate-limit discipline
Before each poll, the remaining core quota is read from the FREE `/rate_limit` endpoint; below `WATCH_RATE_MIN` (default 200) the watcher **backs off** (4× the interval, capped) and logs `RATE-LIMIT`, instead of hammering into the observed **HTTP-403** wall. The overall timeout is checked **before** the rate gate, so a backoff can never starve it.

### E. The lock fd is closed on every NON-successor child (the successor KEEPS it)
The interval `sleep`, each per-PR watcher, and **every poll child** (`gh api rate_limit`, `gh run list`, `gh pr/issue view`) now release fd 9. The detached **successor is the deliberate exception** — it must KEEP fd 9, because that inherited descriptor IS the atomic hand-off (§F). Without the poll-child fix, a hung `gh` kept the flock after the main script died, and a takeover's bounded `flock -w 5 9` could time out (exit 6). Proven below with a hung-`gh` child.

### F. The stacking RCA (the field report) — the successor INHERITS the flock

**Report:** three processes with identical args were live at once (PIDs 2130365/2142566/2142605) — the exact stacking the lock exists to prevent.

**Root cause (reproduced, R1):** the successor was spawned with fd 9 **closed** (`9>&-`) and then **waited** for the lock. So while the predecessor was still in its exit path, a **holder + a waiter** coexisted, and a later arm's `--takeover` raced the waiter → 2-3 simultaneous identical-arg watchers. **Measured on the shipped scripts** (a stub fires a verdict every poll, so the watch hands off every poll; the probe asks `flock -n` for the lock every 20ms):
```
$ /tmp/opencode/lock-continuity.sh
lock held continuously across auto-rearm successions: samples=174 unlocked-windows=0
```
`0` unlocked windows = the successor holds the flock across every hand-off (a waiting successor would show windows; a gap would let a second arm in).

**Fix — the ATOMIC HAND-OFF:**
- `watch_rearm` now **INHERITS fd 9** (drops `9>&-`) and marks the child `WATCH_INHERITED_LOCK=1` + `WATCH_PREDECESSOR_PID=$$` (`WATCH_IS_SUCCESSOR` was removed outright — the inherited-lock flag is the signal).
- `watch_lock_auto` short-circuits when `WATCH_INHERITED_LOCK=1`: the child **already holds the flock** (the same open file description) — it does **not** acquire, does **not** wait, and does **not** close the fd. The lock is therefore held **CONTINUOUSLY** across the swap: **no gap** (a new arm can never slip in) and **no waiter** (never a second live watcher).
- `watch_wait_predecessor` makes the successor wait (bounded, default 15s) for the predecessor PID to vanish before it polls, so **at most ONE** process is ever in the poll loop.

**Committed regression guard (the required "N fires → one live watcher" assertion):** a new assertion drives the REAL `watch_rearm` from a process that holds the lock and asserts, from the probe child, the three properties whose absence reproduced the field report: `inherited=1` (**`WATCH_INHERITED_LOCK=1`**), **already holds fd 9** (`flock -n 9` succeeds on the inherited descriptor), and a **predecessor PID** is set (so it will not poll before the predecessor exits). Together they make "spawn successor, then exit" provably free of a second live watcher: the successor cannot start polling until the predecessor is gone, and no arm can slip into the lock gap because there is none. The field report's three live PIDs (`2130365`/`2142566`/`2142605`) are the case this fails without the fix.

## The RCA — three requirements
The mission's RCA named **three** required fixes (not five); the rest were found and fixed during testing:
1. **One-shot exit → `--auto-rearm`** (A).
2. **No single-instance lock → the flock lockfile** (C).
3. **No rate-limit guard → the `/rate_limit` backoff** (D).

Found + fixed during testing: (a) `pr_watch_many.sh`'s `trap 'cleanup; watch_on_exit_common $?'` **lost the real exit code** (bash expands `$?` after `cleanup`), so a takeover re-armed → ping-pong; (b) `_watch_common.sh` clobbered the successor's env flag → the child's identity flag (`WATCH_INHERITED_LOCK`) is never reset by the sourced lib; (c) the rate gate's `continue` skipped the timeout; (d) poll children held the lock fd.
