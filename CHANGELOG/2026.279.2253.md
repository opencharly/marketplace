# 2026.279.2253 — fix(watch): key watch_key on the script basename, not its path (#423)

## Summary

`watch_key` hashed the **full script path** together with the args. The watch lock lives in a **shared** runtime dir (`$XDG_RUNTIME_DIR`/`$TMPDIR`), so the same logical scope invoked from two checkouts — a session rooted at the umbrella and one rooted in a worktree — produced **two keys and therefore two single-instance locks** (measured live in opencharly/opencharly#408: `holder: 594550 598912`).

This keys on the **script basename + args**. One scope is now one lock from anywhere, while different scripts (`gh_watch.sh` vs `pr_state_watch.sh`) keep distinct keys.

**Byte-compat, stated exactly:** a **bare** single-arg caller — `watch_key hung-lock-test` — hashes exactly as before (the basename equals the arg, and no separator is emitted when no args remain). A **path-shaped** single-arg caller changes by design — that change IS the fix. All three cases are asserted.

Closes opencharly/marketplace#423.
