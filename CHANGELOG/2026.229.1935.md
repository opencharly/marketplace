## Why this leg exists

`charly#289` merged `charly/main` into its branch after `charly#296` landed, so its source now
carries both cutovers' candy edits. The projection did not, and `marketplace drift` measured the gap
as a pair rather than a single number:

```
before   marketplace drift   EXIT 1 — 11 generated artifact(s) are stale
after    marketplace drift   EXIT 0 — clean (400 artifact(s) on disk match their sources)
```

The pair is the evidence. Either figure alone is a tree-state claim that goes stale the next time
anything merges; together they state what this leg *did*, which does not.

**The before-figure moved during review and had to be re-derived** — it was 9 when this leg was
opened and is 11 now, because each source fix the review produced added another artifact the base
does not match. A pair is more durable than a single number and it is not immune: the *before* half
is measured against a base, and it changes whenever the branch does.

## The ollama corpus is deliberately NOT regenerated

Three artifacts under `ollama/skills/` are left exactly as `main` has them, byte for byte. **A
regeneration would delete 97 lines that exist in no source.**

```

```

`OLLAMA_VERSION` appears in **no candy** on `charly/main`; `charly ollama` appears in **no candy** on
`charly/main`. `plugins#191` landed all three from `charly@04b89ced` on branch `feat/ollama-plugin`,
**which was deleted afterwards.** So these artifacts are not derivatives of a source that has drifted
— they are the **only surviving record of a candy that exists nowhere**, and the tracked issue is
[`charly#291`](https://github.com/opencharly/charly/issues/291).

> **"Generated files are safe to regenerate" assumes the generator's input still exists.** When a
> producing branch is deleted after its projection lands, the projection is not a derivative — it is
> the artifact.

The prune is what `generate` is specified to do, and it is correct in general; it is wrong here
because the input is gone. Recoverability from git history does not answer it: **a pruning commit is
not a signpost**, and nobody reading `main` a month from now would know to look.
