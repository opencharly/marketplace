# 2026.302.0951 — chore(refs)!: the container-nesting body is published without the retired builder selector

Closes #600

## Summary

Head `e31ce5e6ed5d1f412417adad52ec11f838429353` — 2 files changed, 2 insertions(+), 2 deletions(-).

**The defect.** The corpus published the `container-nesting` skill body from `layer-container-nesting` at `v2026.293.1724`, and that body's `Env` row still set `CHARLY_BUILD_ENGINE=podman` — the **retired builder selector**. The contract retired it: `EngineConfig.Build`, `ResolvedRuntime.BuildEngine` and the `CHARLY_BUILD_ENGINE` key are gone from `spec/hostenv`, and a leftover `engine.build: docker` is INERT (`spec/hostenv/retired_build_selector_test.go`). The corpus therefore taught every harness that loads it a knob that cannot be turned.

**The RCA.**

- **Mechanism** — the corpus is a PROJECTION: `charly marketplace generate` reads this repo's refs list (`candy/charly-marketplace/charly.yml`) and copies each pinned repo's skill body. The owner had already cut the name out of the candy, the skill body and the README in one cutover (opencharly/layer-container-nesting#16, tag `v2026.302.0925`), but the corpus's ref still pointed at the owner's previous tag — so every regeneration republished the old body unchanged.
- **Missed control** — the corpus's drift gate proves FIDELITY to the refs list; it cannot see that a ref is behind its owner's newest tag. A corpus ref is advanced by a manual act (the daily refresh advances to the owner's newest MERGED tag, so a tag minted after the refresh ran waits for the next day), and nothing in this repo reports "this ref is behind its owner" the way the consumer-currency report reports the corpus's own consumers.
- **Blast radius** — every harness that loads the corpus's `distros` family: the published body told agents to set a retired selector.
- **Root fix** — advance the one ref to the owner's tag and regenerate in the same commit. The corpus may not hand-edit a projection (it is generated output), and the owner may not edit the corpus.

**What lands.**

| file | what changes |
|---|---|
| `candy/charly-marketplace/charly.yml` | the refs list: `layer-container-nesting` advanced from `v2026.293.1724` to `v2026.302.0925` |
| `distros/skills/container-nesting/SKILL.md` | the projected body: the `Env` row loses the retired `CHARLY_BUILD_ENGINE=podman` and keeps the three live contracts |

**The claim.** The retired name is gone from the published tree — the claim-keyed grep over this corpus, history exempt, returns nothing on this commit and exactly one hit before it. The sweep is scoped to the retired builder selector, which is what this producer cut over; the org-wide control for the whole class of retired names is filed as opencharly/opencharly#799.
