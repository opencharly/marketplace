The guidance that now ships says three things the pinned prose used to get wrong. The `currency` mode of the one pin verb **is** in a released binary (measured 2026-10-23 on the built `2026.295.1709`), so the earlier claim that it was not — and the advice to MEASURE the question by hand — was FALSE and is deleted; a hand-built `<path>: <recorded gitlink> vs <remote default-branch HEAD>` table is the second implementation of a verb that already answers it. The guidance carries the verb's **shapes and states** as rules and none of its **counts**, because a count is a live reading of the org's remotes rather than a constant. And the umbrella's own commands are described by what they are: `charly task init` materializes a derived working set (blobless, never shallow; the mode travels in the environment, never as a task parameter), `charly task sync` needs the full set because a sync over a tree it could not fully advance must never report success, and `charly task verify` covers the materialized paths only — an unmaterialized path is *uninitialized (pin audited, no checkout)*, a notice, not a failure. The three task names that no longer exist are gone, each in its own way: `policy-b` is replaced by `pin-check`, `omarchy-agents` and `pi-forks` are deleted outright, and `self-test` is kept and widened to cover the submodule initializer.
