# 2026.332.0120 — feat(lint)!: require the R11 plan conformance map in the PR body

Refs opencharly/opencharly#1336

## Summary

R11 fires twice: over the plan once the R12 round names its winning candidate and before the first
implementation edit, then over the diff before the push. The map is the artifact, and this repo's
linter is where every consuming repo inherits the check — the rulebook's mandate alone would be a
promise no gate keeps.

`## Rulebook compliance` must now carry a `### Plan conformance` block:

- the `**Winning candidate:**` line;
- one row per planned change, naming the DESIGN requirement that governs it and the sentence of it
  the change satisfies; the disposition set is exactly `conforms` and `debt filed #<n>` (whose
  number must also be under `## Filed issues`);
- **`amends DESIGN` is not a disposition.** R11 is conformance, and a design is never edited to fit
  an implementation. The finding says so and points at the redesign-or-operator path.

Two one-line forms cover the rest: `No DESIGN-governed surface — <reason>` for a change that touches
no governed surface, and `Design change — <reason>` for the operator's own DESIGN cutover (DESIGN
A.6), which must paste `design-check: all controls pass`. Its **maintainer sign-off is a PR
comment** and stays the validator's T4 account check — a body-linter cannot see a comment, and
faking one in the body is exactly what this form must not admit.

The map's agreement with the **diff** is deliberately not checked here: every repo runs this
linter and only the umbrella reads a diff. `scripts/check-pr-body-diff.mjs` owns that half.

Fifteen new legs: eleven RED fixtures (a malformed map must fail) and four GREEN controls (a valid
shape must pass). The RED ones fail if the check is removed; the GREEN ones pass either way, and
they exist because the first implementation broke those shapes.

| leg | kind | what it refuses / protects |
|---|---|---|
| the map is required | RED | a body with no `### Plan conformance` block |
| a bare no-surface line | RED | `No DESIGN-governed surface` with no reason |
| `**Winning candidate:**` | RED | a map that names no candidate |
| the disposition set | RED | anything but `conforms` / `debt filed #<n>` |
| a bare `conforms` | RED | a disposition with no evidence, against "show that it CONFORMS" |
| `debt filed #N` | RED | a debt row whose number is absent from `## Filed issues` |
| `amends DESIGN` | RED | a design edit offered as a disposition, with the redesign-or-operator pointer |
| the `Design change` form | RED | that form without the design-check output |
| a bare design-change line | RED | `Design change` with no reason |
| an empty map | RED | a heading with neither a table nor a one-line form |
| the requirement cell | RED | a row whose requirement names nothing, the hole the validator found on this PR |
| the no-surface form is clean | GREEN | a governed-surface-free change passes |
| a blank line after the heading | GREEN | the shape every real body uses, which the first implementation broke |
| evidence after the disposition | GREEN | `conforms — <evidence>`, the way authors write it |
| a `§` or a definition in the requirement cell | GREEN | the three legal names: D-id, `§`, backticked definition |

Every RED leg above was found by the org validator on THIS PR's own bodies, not by its unit tests —
the fixtures encoded the implementation's own idea of the shape. That is why they are fixtures now.
