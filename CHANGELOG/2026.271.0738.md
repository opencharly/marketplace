# 2026.271.0738 — fix(scripts)!: verdict gate on the run COMPLETION time — no stale fire

## Summary

Fixes the **stale-fire** field bug: `scripts/pr_watch_many.sh` fired `WAKE VERDICT` on a validator run **~3 hours old** (tag `v2026.271.0420`).

**Root cause (R1).** The signal-1 guard was `if [ -n "$prev" ] || { [ -n "$cepoch" ] && [ "$cepoch" -ge "$ARM_EPOCH" ]; }` — i.e. it fired whenever the run **id differed from the seed id**, treating the timestamp gate as a mere fallback for an empty seed. That false-fires whenever the "newest completed" run **CHANGES from one OLD run to a DIFFERENT old run** — a seed/poll ordering shift, or a transient seed failure at arm time — both of which completed long before arm time. The `gh_watch.sh` verdict gate had the identical shape.

The `watch_family_test.sh` assertion "stale run never fires" was a **false positive**: it armed with the stale run ALREADY seeded (seed == poll → no change → no fire), so it never exercised the divergent case, and its fixtures omitted `createdAt` entirely — so the assertion could not detect the bug.

**Fix (both scripts).**

- `watch_run_latest` now returns the run's **COMPLETION** epoch (`updatedAt`; field `completedEpoch`) — the only reliable newness gate.
- `pr_watch_many.sh` signal 1 and `gh_watch.sh`'s `verdict` gate now require **`completedEpoch >= ARM_EPOCH`, unconditionally**. The run-id compare is retained only as a SECONDARY guard against re-reporting the SAME run. An empty/unknown seed still adopts its first observation as the baseline **without** firing.
- `pr_watch_many.sh` is now documented **REPO-SCOPED**: it fires on ANY newer validator run in the watched repos, **including another session's PR**. To watch ONE PR, arm `gh_watch.sh` on `owner/repo#<n>`.

**Regression locked.** `watch_family_test.sh` gained a sequence-aware stub (the seed read can differ from later polls) and, per tool:

| Case | Assertion |
|---|---|
| old seed, then a DIFFERENT old run | **must NOT fire** |
| empty seed, then a pre-arm run | **must NOT fire** |
| a run completing AFTER arm | **must fire** (positive control) |
| a pre-existing comment (seeded) | must NOT fire |

**Closes / relates to:** the field report on `marketplace` `v2026.271.0420`; relates to opencharly/layer-charly-internals (the skill `git-workflow` § "A 'new' event must be genuinely newer" — its source leg is the sibling PR).
