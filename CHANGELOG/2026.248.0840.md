Everything outside `candy/charly-marketplace/charly.yml` is **regenerated output**, not an
authored edit. A changed `SKILL.md` or reference doc means the OWNING repo changed that text
in its own candy manifest and tagged it; `charly marketplace generate` then reproduces it here
byte for byte. This PR PROPAGATES that content — it does not author it, and it cannot review
it, because the owning repo's own `pr-validator` gated it before the tag existed. If such a
file needs changing, the change belongs in the owning repo, not here: an edit made here is
overwritten by the next generate.

The refs list is the ONE generation input, and every entry is a CalVer pin. Hand-maintained
pins go stale silently — the corpus keeps building, the drift gate stays green, and the
published skill is simply an old one. That is the failure the candy de-submodule cutover
removed for a single charly pin; this workflow removes it for the remaining 176.

The content is not unreviewed: each pinned repo validated its own change through its own
`pr-validator` before tagging. This republishes what those repos already landed.

## Harness rulebook compliance

- **R1 zero warnings:** the refresh script reports unresolved repos explicitly and leaves
  their pins untouched rather than guessing.
- **R3 no duplication:** one refs list, one owner.
- **R4 no workaround:** every new pin is a MERGED CalVer tag on the owning repo — no branch
  refs, no version-less refs. Tags are compared NUMERICALLY, not lexicographically.
- **R5:** the pins are replaced, not appended to.
- **R6 git safety:** a fresh branch per run; no force-push; no push to `main`.
- **R8 artifact invariants:** the corpus is regenerated by the tool, never hand-edited.

## Authorship

**No `Assisted-by:` footer, deliberately.** Rule A1 requires that line on an *AI-authored*
PR body. This body is not AI-authored: it is emitted verbatim by a fixed `printf`-style
block in `.github/workflows/refresh.yml`, with no model in the loop at any point — the only
variables are counts and command output. There is therefore no harness and no provider model
to name, and the previous line here —

> `*Assisted-by: GitHub Actions opencharly/marketplace-refresh (fully tested and validated)*`

— was BLOCKED for exactly that reason: `opencharly/marketplace-refresh` is a repository, not
a provider model, so the line claimed an attribution that does not exist. Inventing a
model-shaped string to satisfy the pattern would be a false claim, which is the thing the
rule exists to prevent. Naming the generator honestly is the correct resolution.
