## Why the reconcile change is a correction, not only an addition

`build/skills/reconcile/SKILL.md` asserted idempotency twice without qualification
("Edits are comment-preserving … and idempotent", "Idempotent: a second run
rewrites nothing"). That holds for the default mode, whose target is the newest
version ALREADY referenced — a fixed point after one run. It does not hold for
`--remote`: `reconcileTargetVersion` returns `GitLatestTag` without consulting the
referenced set at all, so the target is whatever the remote's newest tag is at
call time, and a re-run after a sibling repo publishes moves every pin again.

An unqualified idempotency claim on a command that rewrites version pins is the
kind of divergence that costs a cutover its evidence, so both claims are scoped.
