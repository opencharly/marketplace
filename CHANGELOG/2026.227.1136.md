## The R4a fix, and why this entry was rewritten

A first revision of this cutover put reader-facing repo-only instructions on two
published pages, and an earlier draft of THIS entry described that revision
rather than what shipped. Both are corrected here.

The defect: `/charly-image:layer` is the kind bucket — read by anyone authoring a
candy anywhere — and it asserted unconditionally that a candy's prose is
published, that editing it fails `task docs:drift`, and that it requires
re-pinning the site candy. Every clause is false for a candy outside this
repository. Separately, `/charly-build:docs` reintroduced five `task docs:*`
targets as numbered reader steps into a body that `2b3dcae` had deliberately
cleared of exactly those, five days after R4a landed.

The entry is rewritten rather than patched because the claim-keyed sweep R1
requires covers a cutover's own freshly-drafted narrative — the CHANGELOG, the
PR description, the commit message — not only the code it describes. Three
claims here were false: the artifact count, the location of the landing
sequence, and the shape of the layer pointer. None had been released.

## Why the reconcile change is a correction, not only an addition

`build/skills/reconcile/SKILL.md` asserted idempotency twice without qualification
("Edits are comment-preserving … and idempotent", "Idempotent: a second run
rewrites nothing"). That holds for the default mode, whose target is the newest
version ALREADY referenced — a fixed point after one run. It does not hold for
`--remote`: `reconcileTargetVersion` returns `GitLatestTag` without consulting the
referenced set at all, so the target is whatever the remote's newest tag is at
call time, and a re-run after a sibling repo publishes moves every pin again.

An unqualified idempotency claim on a command that rewrites version pins is the
kind of divergence that costs a cutover its evidence, so both claims are scoped.
