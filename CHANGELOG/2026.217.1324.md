# 2026.217.1324 — the agent roster inherits the operating model

Every agent definition already pins `model: inherit`, so the whole roster —
teammates, validators, and the sub-agents — runs whatever model the operating
session runs. The execution-model reference still said the default topology was
"a **Fable 5** orchestrator driving **Sonnet 5** teammates and validators" and
told operators to set a cheaper default in `/config`.

That sentence was load-bearing in the wrong direction. It named models that are
not part of this repository's machinery, it rotted the moment an operator ran
the same model for both roles (which is the point of `model: inherit`), and it
pushed operators toward a spend pattern the inherit mechanism exists to avoid.

The reference now states the tier split RELATIVELY — the orchestrator is the
most capable model the session runs, teammates scale ×N on the operating model
— and names no model anywhere. The only way a model is ever named is an
explicit per-spawn `model:` override, which remains available for a unit that
genuinely needs a different one.
