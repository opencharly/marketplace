# 2026.295.0300 — feat(coord)!: the coordination closed set is nine labels — WAITING, HOLDING, CLEARED

## Summary

The coordination grammar's closed set is nine labels, and this repo owns **two halves** of
that contract — the shell implementation and the generated corpus that carries the same
grammar. Both move in this PR, because a corpus that names one set and a tool that
accepts another is a grammar with two answers.

**And a third thing moves with them: the control that missed a body defect.** The
validator's second round blocked this PR on a sentence in the body that no mechanical
check here could see — the Summary said the `strict-policy` skill "carries the new
grammar" while the body's own detail paragraph said that file "touches no coordination
label". Both statements were true on their own; only a comparison of the two finds it.
The third round found the same class one step further along: the Summary said "Two of
those hunks are carried prose" while the table the body itself pasted had three, and only
a comparison of a count with a table finds that. `scripts/pr_body_lint.py` now makes both
comparisons, so the class is closed here rather than waiting for the next reviewer to read
carefully. The rules are narrow on purpose, and they are calibrated: each fires on the
blocked text and on nothing else in 944 merged bodies.

`BLOCKS` used to mean two different things in one document: "this blocks the merge" in
the validator's verdict vocabulary, and "I am blocked" in a coordination comment. The
grammar now shares **no** token with the verdict vocabulary:

    CLAIM · OWNING · HANDING OVER · TAKING OVER · WAITING · HOLDING · CLEARED · STATUS · RESOLVED

`BLOCKS` splits by direction, so the first line states which side is speaking: `WAITING`
is the blocked side ("I am waiting on you"), `HOLDING` is the blocking side ("I am holding
you up"). `UNBLOCKS` becomes `CLEARED`. The set is closed and it is the whole set: a
comment whose first non-blank line is any other word is not a coordination comment, so a
gate looking for one does not count it. There is no exception and no grace period — a
thread answered under the old labels is answered again in the new grammar.

**The two halves.**

- `scripts/coord.sh` — the single generic implementation of the grammar. It states the
  list **exactly twice**: the `VERBS` array that drives validation, and the `--help`
  prose, which `usage()` prints verbatim. It used to state it **three** times — the
  header prose also enumerated the set, as the quotation of the rule it implements — and
  the third copy was the defect the validator's first round found: nothing compared it,
  so it could drift silently while the file advertised a set the tool does not accept.
  The header now points at `--help`, and `scripts/coord_test.sh` asserts the property of
  the file that keeps it that way. The suite carries four closed-set assertions — the
  **round-trip** (the array and the `--help` prose list the same labels; a `--help`-only
  edit passes the per-label loop while the tool rejects the verb it advertises), the
  **identity** (the array *is* the canonical nine, in order), the
  **stated-exactly-twice** property (a *statement* of the set — a maximal run of
  consecutive lines naming three or more of the nine labels — appears exactly twice,
  in the `VERBS` line and in the `--help` block; the labels are matched in any
  separator and any case, so a re-added copy fails however it is spelled, and a single
  label in ordinary code is prose, not a copy), and the **no-retired-label** check
  (the tooling does not grandfather). The test's vehicle verb becomes `WAITING`.
  `scripts/gh_watch.sh` names the list in prose only — it performs no verb matching — so
  its one mention is reworded.
- the **generated** corpus (`internals/**`) — regenerated from the refs list, never hand
  edited. The refs list advances to the wave-1 tags of the two layer repos that own the
  authored sources (`layer-charly-internals` v2026.294.2355, `layer-charly-internals-extra`
  v2026.294.2355), and the corpus follows them: the `git-workflow` skill, its
  multi-repo-coordination reference, the pre-validator self-audit, the `agents`
  hooks-and-lifecycle reference, the `cutover-policy` skill and the `pr-validator`
  agent all carry the new grammar.
