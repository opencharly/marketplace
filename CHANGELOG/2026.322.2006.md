# 2026.322.2006 — feat(coord): make the session footer mandatory, name its harness, and print it on any harness

## Summary

This is a producer leg of opencharly/opencharly#1119. Every attributed PR body, from an agent session or a model-free bot, ends with a session footer that traces it to the session or run that wrote it. Head: `958519452ca9bea113289ca96fa5d2dd65b22d6a` — 5 files, +195 −24.

- **`pr_body_lint.py`.** A body that carries an `Assisted-by` trailer is attributed, so it must end with the session line directly before the trailer:

  ```
  *Agent: `<slug>` · <Harness> session `<id>`*
  ```

  The line may also carry `(subagent of `<parent>`)` after the slug, and the trailer must name the same harness. The grammar is defined once, as `SESSION_LINE`. A human body with neither marker still passes. Older shapes are refused: a bare `Agent: lead`, or a line with no harness or no backticks.

  The footer is judged on the body's prose only. A trailer pasted inside a fence, such as `coord.sh --footer` output, is evidence, so it no longer reads as a buried footer. It also never excuses a missing prose footer: a body whose only trailer sits in a fence is refused.
- **The model-free refresh bot.** It is an attributed body too, so there is no exemption. `.github/workflows/refresh.yml` now writes this line before its trailer:

  ```
  *Agent: `refresh` · GitHub Actions session `<GITHUB_RUN_ID>`*
  ```

  The workflow is the slug, GitHub Actions is the harness, and the run id is the session. A refresh PR traces to the run that wrote it.
- **`coord.sh`.** It writes exactly the session-line shape, with the harness in the `Agent:` line. `--parent` names the parent of a subagent. `--footer` prints only the two footer lines, so any harness can close a PR body with the same code that closes a coordination comment. When the caller names neither `--harness` nor `--session`, both are read from the harness's own environment:
  - `CLAUDE_CODE_SESSION_ID` → Claude Code
  - `DSH_SESSION_ID` → DeepSeek Harness

  Both halves come from one source or neither does. OpenCode and pi expose their ids only to plugins, so they pass them through `COORD_HARNESS` + `COORD_SESSION`.
