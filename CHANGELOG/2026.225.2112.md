# 2026.225.2112 — codify the sandboxed-/tmp Go + golangci-lint environment constraints

Regenerated from the superproject's `candy/charly-internals/charly.yml` manifest edits via `charly marketplace generate`. Two skill files changed:

- `internals/skills/go/SKILL.md` — new "Environment constraints — sandboxed /tmp + Go temp dirs" section: some dev hosts (a sandboxed runner, a small tmpfs `/tmp`) cap writes to the system temp dir at a few tens of MB per command regardless of the free space `df` reports; Go builds and golangci-lint routinely exceed that, and the failures look like tool bugs ("disk quota exceeded", "parallel golangci-lint is running") when they are environmental. Run Go builds/tests with `GOTMPDIR=~/.cache/go-tmp`; golangci-lint v2 locks at `$TMPDIR/golangci-lint.lock` (a missing TMPDIR dir → ENOENT → the false "parallel golangci-lint is running" report); the pre-commit-gate hook already redirects its lint temp dirs to `~/.cache/charly-gate-lint/`.
- `internals/skills/go-quality/SKILL.md` — the pre-commit-gate hook paragraph gains the root-fs lint temp-dir detail: the hook redirects its golangci-lint run to `~/.cache/charly-gate-lint/`, sets `GOTMPDIR`/`TMPDIR` to subdirs it creates there, and creates the subdirs before running golangci-lint because a missing TMPDIR makes the lock open fail with ENOENT — reported as "parallel golangci-lint is running", a false positive that blocks every commit on hosts where the dir does not pre-exist.
