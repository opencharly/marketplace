# 2026.216.2320 — the pr-validator gets teeth on documentation

A documentation-only change class buys a lighter RUNTIME gate. It was also, in practice, buying a
lighter review — and prose ships defects exactly like code does, just harder to see, because prose
that is confusing still parses.

Phase 1b adds documentation scrutiny for reader-facing narrative pages (`README.md`, `VISION.md`,
`GRIEVANCES.md`, `AGENTS.md`, and the hand-authored site pages). Generated trees are exempt — their
source is the thing to fix.

## The cold reader is mandatory, and it is not the validator

A validator cannot judge whether a page teaches a stranger, because it has read the skills, the
diff and the PR body; everything the page fails to explain, it supplies from memory without
noticing. Simulating a newcomer does not work. Phase 1b requires SPAWNING one, forbidden every
source but the changed pages, and asked for the sixty-second test, from-memory definitions, where
it got lost with exact quotes, unsupported claims, and what it still cannot answer.

Its findings are findings, not suggestions. A page a competent engineer cannot follow is defective.
If the reader reports nothing substantive, the verdict must say so — silence has to be visible, so
a skipped reader cannot masquerade as a clean one.

## Twelve mechanical checks, each from a real escape

Contradiction sweep · undefined-term sweep · asserted-vs-demonstrated · reader-state claims · counts
re-derived from the artifact **and reconciled against each other** · **gate probativeness** · re-run
every sweep the body claims · R4a binary-only commands · excerpt integrity · cross-surface drift ·
**source liveness** · abbreviations. Twelve named, twelve listed — the count and its set reconcile,
which is what check 5 asks of everyone else.

Gate probativeness is the transferable one: *what mutation would make this gate fail?* If nothing
would, the gate is decoration and citing it is a false claim however green it is. It caught two
findings in a single PR body — a `docs:drift` no-op offered as proof a page was generated when
deleting the generator still passed, and a site build offered as proof a config line was safe when
a dead sidebar link builds green and renders on 852 pages.

## The standing question

*What surface does this change touch that no gate's scope includes?* Both generator defects found
in this program were the seam between gates, each individually correct about its own scope.


## Six amendments from Phase 1b's first live use

Phase 1b was validated against a real PR (opencharly/docs#10) the day it landed, and the validator
running it returned a critique of the spec alongside its verdict. All six gaps are now closed.

**The big one: 1b had no committed-source check.** Every mechanical item read the *page*, so a page
could be internally flawless and still be a projection of source that exists nowhere. The two
findings that would have published false statements about shipped behaviour were invisible to all
eleven items, and were found by accident. New item 11, **source liveness**: resolve each generated
page's source, confirm it is landed rather than dirty, confirm prose about code behaviour describes
committed code — and treat *"the companion PR carries it"* as requiring that PR to exist.

**Gate probativeness now mutates INPUTS, not only logic.** A gate whose logic is sound can still be
vacuous because of what it reads. For anything reading the working tree, the mutation is `git stash`
in every repo it touches. Promoted to a standing question, because four separate findings in one
program turned out to be a single pattern: reaching for the nearest green signal instead of the one
that would go red if the claim were false.

**Counts must be reconciled against each other, not only re-derived.** Per-number re-derivation
passes a *population swap* — two totals for what a reader takes as one set, both individually
correct. That is worse than a wrong number, because there is no wrong figure to point at.

**The contradiction sweep runs against the post-merge page**, and a collision with either side in
the diff is blocking. Otherwise the item is defeatable by leaving the older half untouched and
calling it pre-existing.

**Removing a demonstration is a regression**, even when the replacing prose is better written.
Prose quality and evidence are separate axes; a diff trading a worked example for a tidier table has
weakened the page.

**The cold reader's weighing rule gains its missing category** — *misallocation of the reader's
attention* — and one question only it can answer: which section would you delete, and which is
missing. The finding that forced this: *"the prose is arguing with a previous reader I am not."*

Also clarified: W0 forbids bootstrapping another checkout to validate *from*, not a read-only
scratch worktree driven from the superproject root — which is the correct way to run a mutation
test without leaking into a shared checkout.


## Skills are in Phase 1b's scope — the amendment its own PR proved necessary

The validator running Phase 1b against **this PR** found that the scope list excluded `SKILL.md`
entirely, and that this PR's defects were precisely the class 1b exists to catch. It applied 1b
anyway on judgement; a validator reading the applicability line literally would not have been
required to look — so the check that found the defect was optional at the moment it was needed.

Skills are now named in scope, with the reason written down rather than assumed: a `SKILL.md` reads
like an internal note, which invites the idea that 1b is about the website. Every skill is published
to opencharly.ai and read by strangers, and source liveness is exactly what a skill needs, because a
skill's whole job is describing code.

**The cold reader gains a scoping rule.** An unbounded "spawn a sub-agent" produces mush against a
thirty-file diff, and *"would you have kept reading?"* is the wrong question for a reference page.
1b.0 now says to name a handful of pages, to ask a reference page whether it answers what it claims
and where it sends the reader next, and to **skip the reader explicitly in the verdict** when the
diff holds nothing a stranger would read start-to-finish — rather than running it hollow.

**Item 12 ships a runnable command.** Stripping fenced and inline code before extracting uppercase
tokens is a parse, not a grep; items 4 and 7 give runnable forms and 12 did not, so it degraded to
eyeballing. It now carries the script, self-tested against the spec file it lives in.


## Testing Standard 8 — R9 covers plugin binaries

`/charly-check:check` gains a standard, and the renumbering it forced is recorded here because it
changes what a phrase means repo-wide.

A verb served OUT-OF-PROCESS loads the packaged plugin from `/usr/lib/charly/plugins/` unless
`CHARLY_PLUGIN_DIR` points at your build (`charly/plugin_loader.go`: `bakedPluginDirs()` returns the
override *then* the FHS dir, and `bakedPluginBinary` returns on the first hit). So **a live run of an
out-of-process verb — and any bed exercising one — proves nothing about your rebuild by default.**
Both a live run and a full `check-enc-pod` bed shipped green that way during the cleartext-warning
cutover before anyone noticed neither had loaded the plugin under test. Same family as invoking a
stale `/usr/bin/charly`.

**The renumbering is the part worth flagging.** Inserting a standard at 8 shifted the tail, so
*"the 10 Testing Standards"* is now *"the 11"* — a phrase that appeared in this reference page four
more times and in eleven sibling skills, plus two ordinals inside Standard 0 pointing at the
fresh-rebuild gate, which moved from 10 to 11. All swept.

That sweep is the second population-swap this entry has had to record, and both were introduced by
the PR adding the check that catches them. A number and its named set can each be individually
correct and still disagree; the only defence is re-deriving the claim rather than the count.
