**Why it matters beyond a name.** Two repos declared one skill name; the corpus tolerates both, but the umbrella's **derived** harness binding is a flat farm named after the skill, so it fails outright — `FAIL: corpus skill name collisions across families (a flat farm cannot bind both)` — which stops `charly task sync` and the whole umbrella pin advance (`opencharly/marketplace#469`). `plugin-crabbox` keeps `crabbox` for its check verb; the CLI candy becomes `crabbox-cli`.

**Four of the five producers were found only after the fact** — the corpus-wide `grep` pasted in *How tested* below is the check that would have caught them, and running it first is what the earlier revision should have done. The chain began with three; a regeneration that should have been clean still carried the old reference in `build/skills/docs/SKILL.md` and `check/skills/crabbox/SKILL.md` — the projections of `layer-charly-build` and `plugin-crabbox`, neither of which had been swept. Those two are exactly what this PR would have published as **dangling** references, and the validator's BLOCK on the first revision is what surfaced them. The reach of a published skill name turned out to be five repos and six PRs.

**The stale `tools/skills/crabbox` directory is deleted here**, and that deletion is deliberate: the generator writes the renamed skill but does **not** remove the old one, so regenerating alone leaves both names side by side — the duplicate-name state this chain exists to remove, silently re-armed while appearing fixed.

That last command is the one that matters, and it is the check that would have caught the two producers this PR was first missing: **no live file in the corpus carries the old reference anywhere.**

**Drag-backwards audit** — a wholesale regeneration reverts landed prose whose candy source is in flight, historically 21 files in `plugins` and 41 in `docs`, and the diff looks identical to a legitimate update. Run before committing:

```console
$ git diff --numstat origin/main | awk '{a+=$1;d+=$2} END{print "added:",a," deleted:",d," files:",NR}'
added: 12  deleted: 12  files: 7

$ git diff --numstat origin/main | awk '$2>$1'      # files losing net lines = the reverts
(none)
```

The only file losing net lines is the stale skill directory this change deletes deliberately; no landed prose is reverted.
