## What changed in the source, and therefore here

- **`ollama/skills/ollama/SKILL.md`** — the candy installs the distro package where one exists
  and falls back to a guarded tarball elsewhere, so the install description changes shape. The
  pin section is rewritten: `OLLAMA_VERSION` IS pinned to a release tag and must stay one,
  because the download cache is content-addressed by the sha256 of the URL and a `latest` URL
  would hash to a single key forever, serving the first tarball it ever fetched. The page
  previously said the candy tracks newest-by-default and that pinning is optional — the opposite.

  The **Box Properties table is deleted rather than corrected.** It stated a `Base` and a candy
  list for a box that lives in a `box/<distro>` submodule; that is a cross-repo composition claim
  no gate in this repo can keep true, and it had already drifted — the table said
  `agent-forwarding, ollama` twenty-seven lines above prose claiming the same box composes
  `ollama-cuda`. What replaces it is the set of properties that ARE stable here (port, volume,
  registry) plus a pointer to `charly box list candies`.

- **`ollama/skills/ollama-layer/SKILL.md`** — the install row states the real mechanism; the
  `/usr/bin/ollama` check is described as UNGATED, which it is (the step carries no `context:`,
  so it runs under `charly check box` AND `charly check live`) where the page claimed
  `context: [build]`; and the description takes opencharly/charly#289's framing, extended to name
  the two backend candies that make it actionable.

- **`ollama/skills/ollama-cli/SKILL.md`** — content unchanged. It stops being an orphan because
  charly#309 adds its source entity, `candy/plugin-ollama`'s `ollama-cli-skill`.

## What this projection deliberately does NOT carry

A full regeneration from that tree also deletes `build/skills/load/SKILL.md` and
`distros/skills/nested-podman-socket/SKILL.md` — skill entities that landed in this repo ahead of
their charly sources — and reverts roughly two dozen further artifacts to a state their own open
PRs have moved past. That is opencharly/charly#323, a separate job with a different blast radius.
A projection PR that quietly reverts other people's unlanded work is the failure mode #323
describes, so this one is scoped to `ollama/`.
