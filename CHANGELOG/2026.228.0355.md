# 2026.228.0355 — the remedy named a field the pages never declared

Cold-reader findings on the pages `sdk#138`'s sweep rewrote, plus the
declaration sites that made its remedy unfollowable.

## The headline

Both new sentences told the reader to *"Set `distro: alpine` explicitly"* — and
`distro:` was declared nowhere a reader authors from. Not in the `VmSource`
struct listing on the page that calls itself *"the authoritative Go reference"*,
and not in the `vm.yml` layout on the page that reference designates as *"the
YAML-authoring companion"*. It appeared otherwise only as a REQUIRED field of a
different source kind.

So the remedy was **unfollowable in exactly the way the original defect was**:
it named the right action and gave the reader nowhere to perform it. Both
declaration sites now carry it — the struct field with its semantics, and a
commented `distro:` line in the layout stating when it is required and what
happens when it is omitted (systemd rendered onto an OpenRC guest; the VM boots
unreachable).

## `charly_install.strategy` — wrong on both pages, in opposite directions

The authoring page documented `auto | none`; `none` hard-fails the closed
schema. The internals pages documented `auto | scp | url | skip`; `url` was
dropped from the Go struct. The real set is `auto | scp | skip`
(`spec/schema/vm.cue:226`), and `VmCharlyInstall` has exactly one field.

**The first fix corrected the enum line and stopped there** — leaving the `URL`
and `Checksum` struct fields immediately below it and two table rows still
documenting `url`. That turned a uniformly-wrong page into a self-contradicting
one, which is worse: uniform staleness at least reads consistently, while a
reference page that contradicts itself three lines apart looks authoritative
while telling you nothing. All six sites are now removed.

Note `deploy.cue`'s separate `charly_install_strategy` legitimately still carries
`url`. Different field, untouched — a class sweep keyed on `url.*strategy` would
have "fixed" it wrongly.

## Also corrected

An Arch contradiction (one line claimed a socket-activated sshd already
listening where another says Arch ships no `ssh.socket`; the host-key-regen race
needs only a LIVE sshd, so the claim was relocated rather than deleted), a
dangling forward reference, an ambiguous step count, and an `apt/dnf` quantifier
that never addressed apk though Alpine now routes through that path.

## The method finding, which outlived the fixes

A validator turned this cutover's own method note back on it:

> Your control table greps only the strings the edit changed. A control keyed to
> the edit is structurally incapable of surfacing a site the edit missed — it
> measures the edit, not the claim.

That is the mechanism behind every incompleteness in this cutover, stated more
precisely than the earlier "sweep the claim, not the string." A string-keyed
sweep and an edit-keyed control fail the same way: both confirm what was done
rather than what remains. The evidence a fix is complete has to come from a
predicate the fix cannot satisfy by construction — here, *"does any surface still
declare a value the schema rejects?"* rather than *"did my edit land?"*

## Corrections to this entry's own claims

**The `distro:` layout claim named the wrong site.** This entry said the line
went into "the vm.yml layout on the page that reference designates as 'the
YAML-authoring companion'." That page is `vms-catalog`; the line went into
`arch-cloud-vm`, a different file. Useful there, but the record asserted a site
the edit never touched — the same defect class this cutover exists to fix, in
the document describing the fix.

Three sites now carry it, named individually rather than counted: the
`vms-catalog` `vm.yml` layout (the site this entry claimed), the `vm` template
layout, and the `arch-cloud-vm` example. `vms-catalog`'s step-2 prose, which
named only the arch/alpine inference and so read as "nothing needed for
debian", is corrected in the same edit.

**And the advice it carried was FALSE for two distros, in the direction that
breaks VMs.** It read "Omit for arch/fedora/debian/ubuntu." Verified at
`sdk@91cc241`: `effectiveDistro` infers **only** `arch` and `alpine`. So
`base_user: debian` with no `distro:` yields `""`, and two things break —
`composePackages` picks `openssh` instead of `openssh-server`, which the
function's own comment says hard-fails cloud-init (`E: Unable to locate package
openssh`, leaving qemu-guest-agent waiting forever), and `sshUnitForDistro("")`
returns `sshd` where Debian needs `ssh`.

The accurate rule: **omit for arch and fedora; SET it for debian/ubuntu, and for
an Alpine image whose account is not literally `alpine`.**

That is worse than the defect being fixed. The original prose was merely
incomplete; this told a reader to do something that produces an unbootable VM.
It came from generalising "the inference handles the common distros" without
reading which distros the inference actually names — an assumption about a
mechanism, stated as guidance, in a document about not doing that.

## The two findings a claim-keyed sweep cannot catch

Three rounds of validation on this cutover converged on one observation, and both
validators reached it independently: **the findings that kept surviving were the
ones that are not string-shaped.**

The `url`/`none` strategy class had a grep-able key. It died the moment the sweep
switched from edit-keyed to claim-keyed — and that switch immediately found two
source-map table rows neither the author nor the validator had flagged. That is
the instrument working.

The two that survived three rounds have no key to grep:

| Finding | Why no predicate fires |
|---|---|
| "a key is missing from a layout block" | absence has no string; the block looks complete |
| "this paragraph's mechanism contradicts that paragraph's" | both sentences are individually true |

The predicate for the first is *read the block against the field list*. For the
second it is *read both paragraphs together* — a contradiction lives in the pair,
never in either half, so no per-line scan can hold it.

**And a partial fix leaves the page MORE inconsistent than before it.** Four times
in this cutover: the `url` removal stopped at the enum and stranded the struct
fields below it; the strategy fix missed a site 125 lines under the edit; the Arch
fix opened a contradiction with an untouched paragraph; and the clause that closed
THAT contradiction opened a third one against the D15 race finding. A uniformly
wrong page is recoverable — a reader distrusts all of it. A self-contradicting page
is worse, because half of it still reads as authoritative.

So the sweep runs against the whole surface AFTER the edit, not against the lines
that were in view when it was made. The edit changes what is inconsistent.

## The fix that propagated a false mechanism to three sites

Correcting the `distro:` advice replaced one false claim with another, and shipped
it to three places at once. The new comments said `effectiveDistro` infers
`arch` and **fedora** from `base_user`. Verified at `sdk@91cc241`, the switch has
exactly two arms — `arch` and `alpine`. Fedora is inferred nowhere.

The list was wrong in **both** directions: it added `fedora`, which is not
inferred, and dropped `alpine`, which is. And the *conclusion* was fine — omitting
`distro:` on Fedora does work, because `composePackages("")` yields `openssh`
(a real Fedora package) and `sshUnitForDistro("")` yields `sshd` (the right unit).
It works by the empty default happening to be correct there, not by inference.

That distinction is not pedantry. A reader told fedora is inferred concludes
`base_user: fedora` steers rendering. It does not.

Worse, the correct rule was already in the same page, 123 lines below, corrected
by this same cutover: *"infers ONLY `arch` and `alpine`."* Both statements shipped
together, and both validators found the collision independently on the two
projections.

**Three separate one-clause repairs also produced false sentences downstream:**

| repair | what it broke |
|---|---|
| `url` strategy removed from the enum | struct fields two lines below left stranded |
| Arch trade-off reconciled | a second mechanism asserted that contradicted D15 |
| "all three deleted" → "two deleted" | left `, and the step…` dangling off a noun phrase, inverting its subject |

The last is the sharpest: a true correction produced a false sentence one clause
downstream, because the replacement changed what the following clause attached to.
**A correction is a new claim carrying the original's full burden of proof — and
its blast radius is the sentence, not the phrase.** Re-read the whole sentence
after replacing any part of it, and the paired paragraph after replacing any
sentence.
