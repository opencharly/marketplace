# 2026.228.0355 — the remedy named a field the pages never declared

Cold-reader findings on the pages `sdk#138`'s sweep rewrote, plus the
declaration sites that made its remedy unfollowable.

## The headline

Both new sentences told the reader to *"Set `distro: alpine` explicitly"* — and
`distro:` was declared nowhere a reader authors from. Not in the `VmSource`
struct listing on the page that calls itself *"the authoritative Go reference"*,
and not in the `vm.yml` layout on the page that reference designates as *"the
YAML-authoring companion"*. It appeared otherwise only as a REQUIRED field of a
different source kind.

So the remedy was **unfollowable in exactly the way the original defect was**:
it named the right action and gave the reader nowhere to perform it. Both
declaration sites now carry it — the struct field with its semantics, and a
commented `distro:` line in the layout stating when it is required and what
happens when it is omitted (systemd rendered onto an OpenRC guest; the VM boots
unreachable).

## `charly_install.strategy` — wrong on both pages, in opposite directions

The authoring page documented `auto | none`; `none` hard-fails the closed
schema. The internals pages documented `auto | scp | url | skip`; `url` was
dropped from the Go struct. The real set is `auto | scp | skip`
(`spec/schema/vm.cue:226`), and `VmCharlyInstall` has exactly one field.

**The first fix corrected the enum line and stopped there** — leaving the `URL`
and `Checksum` struct fields immediately below it and two table rows still
documenting `url`. That turned a uniformly-wrong page into a self-contradicting
one, which is worse: uniform staleness at least reads consistently, while a
reference page that contradicts itself three lines apart looks authoritative
while telling you nothing. All six sites are now removed.

Note `deploy.cue`'s separate `charly_install_strategy` legitimately still carries
`url`. Different field, untouched — a class sweep keyed on `url.*strategy` would
have "fixed" it wrongly.

## Also corrected

An Arch contradiction (one line claimed a socket-activated sshd already
listening where another says Arch ships no `ssh.socket`; the host-key-regen race
needs only a LIVE sshd, so the claim was relocated rather than deleted), a
dangling forward reference, an ambiguous step count, and an `apt/dnf` quantifier
that never addressed apk though Alpine now routes through that path.

## The method finding, which outlived the fixes

A validator turned this cutover's own method note back on it:

> Your control table greps only the strings the edit changed. A control keyed to
> the edit is structurally incapable of surfacing a site the edit missed — it
> measures the edit, not the claim.

That is the mechanism behind every incompleteness in this cutover, stated more
precisely than the earlier "sweep the claim, not the string." A string-keyed
sweep and an edit-keyed control fail the same way: both confirm what was done
rather than what remains. The evidence a fix is complete has to come from a
predicate the fix cannot satisfy by construction — here, *"does any surface still
declare a value the schema rejects?"* rather than *"did my edit land?"*
