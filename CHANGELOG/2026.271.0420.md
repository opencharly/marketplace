### A. `scripts/pr_watch_many.sh` — cross-repo PR-batch watcher

Three generic wake signals (repo set, interval, stall window, validator name ALL configurable; no org/repo/session/date baked in):

| Signal | Fires when | Output |
|---|---|---|
| **0 PR TERMINAL** | a watched PR reaches MERGED/BLOCKED/CLOSED — delegated to the sanctioned `pr_state_watch.sh` (POISON still named distinctly from a verdict BLOCK) | `TERMINAL <STATE> (exit <N>) <repo>#<pr>` |
| **1 NEW VERDICT** | a new `<validator>` run **COMPLETES** on any watched repo — the **progress** signal | `WAKE VERDICT <repo> <conclusion>\|<branch>\|<updatedAt> <run-url>` |
| **2 STALL** | **no new verdict** within `--stallmin` while scopes remain open+unmerged | `WAKE STALL …` + the still-open scopes |

### B. `scripts/gh_watch.sh` — per-item PR/issue event watcher (new)

| Event | Kind | Meaning |
|---|---|---|
| `merged` | STATE (default) | PR merged → **UNBLOCKED** (fires immediately if already merged) |
| `closed` | STATE (default) | closed without merging → find the successor |
| `stall` | STATE (default) | **silence alarm** — no progress for `--stallmin` while open+unmerged → takeover candidate |
| `verdict` | DELTA (opt-in) | a NEW `<workflow>` run COMPLETED in its repo |
| `comment` | DELTA (opt-in) | a NEW comment/review on the item |

### C. `scripts/_watch_common.sh` — the shared helpers (new; R3)

`usage`/`watch_usage`, `watch_is_uint`, `watch_has`, `watch_run_latest` live **once**, sourced by both scripts — nothing copy-pasted.

### The four field-learned requirements — encoded as DEFAULTS, not tips

1. **Silence is an ALARM.** A blocked item emits **no events**, so `stall` is **ON BY DEFAULT**. *The events tell you when something HAPPENED; the stall alarm tells you when something SHOULD have and did not.*
2. **Watch the OUTCOME, not every event.** Default event set = `merged,closed,stall`; `comment`/`verdict` opt-in.
3. **Liveness ≠ progress.** Progress is judged by **artifacts** (a pushed branch, commit, comment, completed run, merged tag), never a session heartbeat.
4. **A "new" event must be genuinely NEWER than arm time — never a stale fire.** An **empty seed is UNKNOWN**, not "no prior run": `watch_run_latest` now returns the run's `createdEpoch`; both watchers adopt an unknown baseline WITHOUT firing, and a `verdict` fires only when the run's `createdAt` is at/after arm time or its id differs from a KNOWN prior.

The runbook (when to arm which watcher, the arm → wake → act → re-arm loop, and the takeover a `stall` feeds) lands in the `git-workflow` skill source + its regenerated marketplace projection (opencharly/layer-charly-internals#41 + the corpus PR).
